# static/js/bundles/map_surfaces.txt — the map's sheet and panel scripts (SNOW-1412).
#
# One filename per line, relative to static/js/, in the order the browser
# runs them. `#` lines are notes. {% js_bundle "map_surfaces" %} renders these as
# separate <script defer> tags in development and tests, and bin/bundle-js
# joins them into static/bundles/map_surfaces.bundle.js for staging and production.
# See docs/decisions/the-map-page-ships-one-script-bundle.md.

htmx.min.js

# favourites.js, which is what both of them require.
place_picker.js

sheet_detents_core.js

# SNOW-879: the shared stale-while-revalidate cache for the three UGC
# panels' rows. Loaded HERE, ahead of every surface partial below, for
# the same reason as the three tags above: all four are defer, so
# document order is execution order, and favourites.js / report.js /
# routes.js each call window.pwaPanelRows.warm() at init. Each guards
# the call with `?.`, so a page that omits this tag degrades to the
# fetch-on-every-open behaviour rather than breaking.
panel_rows_cache.js

# SNOW-658: only one overlay is open over the map at a time
# (window.pwaMapOverlays). Every map overlay — the layers menu, the
# three UGC sheets, the anchored detail popup, the legend card and the
# help coachmark — registers with it and announces its own open, and it
# closes the rest. It replaces the
# hand-wired pairs each surface used to carry, which covered three of
# the fifteen relationships between them. Loaded HERE, ahead of every
# registering module: map_sheet.js registers from attach(), and both
# surface partials below (and the map bundle further down) register at
# their own parse time, so this has to have run first.
map_overlay_exclusivity.js

# SNOW-658: where a map overlay may reach — the floor above the season
# scrubber, the height cap below #map's top edge, and the inset past the
# bottom-right roundel column (window.pwaOverlayBounds). Shared by the
# layers menu (map_basemap_picker.js, in the bundle below) and the three
# UGC sheets. Loaded here, outside the bundle's contiguous run: every
# consumer calls it from a user-triggered handler, never at parse time,
# so it only has to be on the page.
map_overlay_bounds.js

# SNOW-658: renaming a UGC panel row in place — the interaction the
# two renameable panels (downloads, favourites) share, with each
# passing its own commit. Loaded here rather than from either surface
# for the same reason htmx/place_picker/map_sheet are: both callers
# are below, all these scripts are defer, so document order is
# execution order and window.pwaInlineRename exists before either.
#
# It replaced overflow_menu.js on this page for one day, when Hugo's
# SNOW-658 design took the "…" off every panel and nothing here opened
# one. That ruling is gone — see the next block, and
# docs/design-system.md's interaction principles — so both modules now
# load, and this comment is kept only so the swap does not look
# unexplained in the history.
# SNOW-867: the "…" row menus. Loaded HERE, once, because several
# surfaces on this page carry one — the routes panel (SNOW-830), the
# downloads panel, and the favourites panel (SNOW-887) — under the
# rule that replaced SNOW-658's: two or more actions is a "…", one is a
# bare icon. It used to load from _routes_surface.html as that panel's
# own dependency; a second tag there would run the module twice, since
# browsers do not deduplicate script elements by URL.
overflow_menu.js

# SNOW-887: window.pwaShare. Loaded HERE for the same reason as the
# menu above — the routes panel had it as its own dependency until the
# favourites panel became a second consumer, and two tags would run the
# module twice. Deferred scripts run in document order, so pwaShare
# exists before routes.js and favourites.js reach their own top level;
# static/js/map.js reads it from a click handler, long after all of
# them.
share.js

inline_rename.js

# SNOW-711: the server half of that rename — read the row's uuid off
# the pencil, POST the committed name, hand the response back. The
# favourites and routes panels here and the account page's own list
# all did that identically; each still decides what to do with the
# response, which is the only part that differs.
row_rename_commit.js

# The other half of a UGC row's name: pressing it frames that item on
# the map. Loaded here for the same reason as the two above — the
# routes, favourites, field-observation and (SNOW-811) downloads
# surfaces below all delegate to window.pwaRowFocus, and deferred
# classic scripts run in document order. Not loaded on the account
# pages: their rows name the same places, but there is no map on those
# pages to fly, so those rows render no focus button at all.
row_focus.js

# SNOW-752: the third shared row module — recognise a row's own Remove
# landing, so the surface that owns the list can re-read it and tell
# the map. Loaded here, ahead of the three panel modules below, for
# the same reason as the two above: each calls window.pwaRowRemoved
# .watch() as its IIFE runs, and deferred classic scripts run in
# document order. Unlike row_focus.js this one IS also loaded on the
# account pages — their rows carry the same trash, and a list there
# goes just as stale.
row_removed.js

# Keeps every `<time data-relative-time>` on this page true for as
# long as the page is open — the field-observation rows' "reported 2
# hours ago". This is the map: it is opened at the car park and read
# again hours later, out of signal, with nothing re-rendering it.
# Loaded here rather than from _report_surface.html so it binds once
# and is available to any other surface that grows a relative age.
relative_time.js

# SNOW-672: the sign-in gate the three surfaces below all show. Loaded
# here, ahead of them, for the same reason as relative_time.js — one
# owner for the treatment rather than a copy in each module.
signin_cta.js

# SNOW-749: the account half of offline downloads — pushes each
