# The PWA launch: splash to first paint

An installed launch shows the OS's launch screen from tap until the page
first paints, then the page itself. Nothing in the page continues the
splash: SNOW-878 added an in-app overlay for that and SNOW-1112 removed it,
because on a device the hand-over between the two always showed as a flash
([decision](decisions/the-launch-screen-is-the-os-splash.md)). What is left
to get right is that the splash and the page agree on colour, and that the
splash shows the right environment's icon, uncropped.

| | Android (Chrome WebAPK) | iOS (Safari standalone) |
|---|---|---|
| Launch screen | Generated by Chrome from the manifest | `apple-touch-startup-image` PNGs (`bin/build-pwa-splash`) |
| Logo | Manifest **maskable** icon, cropped to a circle | The rounded tile |
| Background | Manifest `background_color` | Baked into the PNG (`--color-bg`, both schemes) |
| Status bar | `background_color`, then `theme_color` at first paint | Black-translucent |

## One source for every value

Everything that differs per environment is a field on
`PWAEnvironmentIdentity` (`apps/public/site_environment.py`), chosen by
`settings.SITE_ENVIRONMENT`. The manifest view and `base.html` read only
that object; neither carries its own colour or icon path.

| Field | Read by | Notes |
|---|---|---|
| `name_display`, `short_name` | manifest, `<title>`, Apple title | |
| `icon_static_dir` + `icon_url()` | manifest icons, `apple-touch-icon` | Goes through the staticfiles storage, so URLs are content-hashed on staging and production. Chrome only re-mints a WebAPK when an icon URL changes. |
| `background_color` | manifest | Equals `--color-bg` in `src/css/main.css`, the page's own background |
| `theme_color` | manifest, `<meta name="theme-color">` | Equals `background_color` on every environment, so the status bar never changes at the handoff |
| `tile_color` | nothing emitted; tests | The icon tile and the favicon fill. The tile is the **only** staging tell |
| `favicon`, `title_suffix` | `<head>` | |

`tests/public/test_pwa_launch_parity.py` renders the manifest and the map
page per environment and checks that they agree: theme-color, background
equal to `--color-bg`, no icon from the other environment, and hashed URLs.

## The maskable icon

Android draws the maskable icon twice. On a Pixel 9 running Android 17 the
splash shows the whole icon as a circle 240dp across. The home-screen
launcher is tighter: it draws an adaptive icon, showing the middle two
thirds of the canvas, with a safe zone of 66dp of 108dp. So
`bin/build-pwa-icons` shrinks the tile until its furthest mark (the
mountain's base corners, or the ends of the "Staging" label) sits at 30%
of the canvas from the centre, and it centres the marks themselves rather
than the tile, whose mountain sits low in its square. The marks can't be
made larger without the launcher cropping them.
`tests/public/test_pwa_icons.py` fails if a mark reaches the edge of that
circle, or sits off centre.

Known gaps:

- **Pre-12 Android.** Chrome draws its own splash, with the icon smaller
  and the app name underneath.
- **Staging on iOS.** iOS shows the production startup images, since there
  is no staging set (SNOW-878; per-environment iOS images are a separate
  ticket).
- **Dark mode on Android.** The manifest has no dark `background_color`,
  so Android's splash and status bar are always the light cream. iOS
  follows the scheme: its startup images come in both.

## Adding an environment

1. Build its icon set: add a `TILE_COLOUR_*` and an output directory to
   `bin/build-pwa-icons` and run it. This writes `icon-192`, `icon-512`,
   `icon-maskable-512` and `apple-touch-icon-180` under
   `static/icons/<dir>/`.
2. Add a favicon with the same tile fill.
3. Add a `PWAEnvironmentIdentity` constant with the new `icon_static_dir`,
   `tile_color`, `favicon` and names. Keep `background_color` and
   `theme_color` at `LAUNCH_BACKGROUND`. Teach `from_settings()` to return
   it.
4. Add the environment to `ENVIRONMENTS` in
   `tests/public/test_pwa_launch_parity.py`, and to the tile-colour test in
   `tests/public/test_site_environment.py`.

## Testing a launch

Automated: `uv run pytest tests/public/test_pwa_launch_parity.py
tests/public/test_pwa_icons.py tests/public/test_pwa_splash.py`.

On a device, follow scenario P3b in
[`testing-scenarios.md`](testing-scenarios.md). Android caches the manifest
at install, so **uninstall and reinstall** after any change to the manifest
or the icons; a hashed icon URL lets an existing install pick up the change
on Chrome's next WebAPK update check, but that can take days.
