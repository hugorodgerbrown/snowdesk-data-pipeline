# The PWA launch: splash to first paint

An installed launch is two surfaces drawn by two owners. The OS draws a
launch screen from tap until the page paints; the page's launch shell
(`templates/includes/_pwa_launch_shell.html`) takes over from there until
the map is ready. The launch looks like one screen only if the shell's
first frame is identical to the OS's last one (SNOW-878, SNOW-1112).

| | Android (Chrome WebAPK) | iOS (Safari standalone) |
|---|---|---|
| OS launch screen | Generated by Chrome from the manifest | `apple-touch-startup-image` PNGs (`bin/build-pwa-splash`) |
| Logo | Manifest **maskable** icon, cropped to a circle | The rounded tile |
| Background | Manifest `background_color` | Baked into the PNG (`--color-bg`, both schemes) |
| Status bar | `background_color`, then `theme_color` at first paint | Black-translucent |
| Shell's matching mark | `icon-maskable-512.png`, 240px canvas, 160px circle | `icon-192.png` at `clamp(96px, 24vmin, 160px)` |

## One source for every value

Everything that differs per environment is a field on
`PWAEnvironmentIdentity` (`apps/public/site_environment.py`), chosen by
`settings.SITE_ENVIRONMENT`. The manifest view, `base.html` and the launch
shell read only that object; none of them carries its own colour or icon
path.

| Field | Read by | Notes |
|---|---|---|
| `name_display`, `short_name` | manifest, `<title>`, Apple title | |
| `icon_static_dir` + `icon_url()` | manifest icons, `apple-touch-icon`, both shell marks | Goes through the staticfiles storage, so URLs are content-hashed on staging and production. Chrome only re-mints a WebAPK when an icon URL changes. |
| `background_color` | manifest, shell's inline first-paint CSS | Equals `--color-bg` in `src/css/main.css` |
| `theme_color` | manifest, `<meta name="theme-color">` | Equals `background_color` on every environment, so the status bar never changes at the handoff |
| `tile_color` | nothing emitted; tests | The icon tile and the favicon fill. The tile is now the **only** staging tell |
| `favicon`, `title_suffix` | `<head>` | |

`LAUNCH_MARK_ICON` and `LAUNCH_TILE_ICON` name the two files the shell can
draw, once, for both the manifest and the template.

`tests/public/test_pwa_launch_parity.py` renders the manifest and the map
page per environment and checks that both sides agree: theme-color,
background, the Android mark equalling the manifest's maskable icon, no
icon from the other environment, and hashed URLs.

## The first frame

The shell's first-frame CSS is inline in the partial, not in `output.css`.
The background is the identity's value, and nothing about the first frame
waits on a stylesheet. Fades, dismissal and the ten-second failsafe stay in
`src/css/main.css`.

The inline gate runs straight after the overlay markup and before the nav:

1. It returns at once unless this is the installed app (`display-mode:
   standalone`, or iOS's `navigator.standalone`) on its first load of the
   session (a `sessionStorage` flag).
2. It adds `pwa-launching--ios` when `'standalone' in navigator`; only
   iOS WebKit defines it.
3. It gives a `src` to the one mark it will show, from a URL rendered into
   the script (never read back out of the DOM). A browser
   tab renders the markup on every page and fetches neither image.
4. It adds `pwa-launching`, which shows the overlay.

"Loading…" fades in at 300ms, hangs below the mark and is absolutely
positioned, so it never moves the logo.

### The Android geometry

Android 12+ draws a launcher icon that has a background on a 240dp canvas
inside a 160dp circle. CSS pixels are dp on Android, so the shell draws the
maskable PNG at 240px with `clip-path: circle(80px)`, centred on the
viewport. These numbers come from the Android SplashScreen documentation.
Confirm them on a device (below), and if they are off, change both values
in the partial's `<style>`.

Known gaps:

- **Pre-12 Android.** Chrome draws its own splash, with the icon smaller
  and the app name underneath.
- **Staging on iOS.** iOS still shows the production startup images, since
  there is no staging set (SNOW-878; per-environment iOS images are a
  separate ticket). So on iOS only, staging hands over from the production
  tile to its own.
- **Dark mode on Android.** The manifest has no dark `background_color`,
  so Android's splash, status bar and launch shell are always the light
  cream. iOS does follow the scheme: its startup images come in both, and
  the shell's iOS branch switches to the dark `--color-bg`
  (`LAUNCH_BACKGROUND_DARK`) under the same `prefers-color-scheme` query.

## Adding an environment

1. Build its icon set: add a `TILE_COLOUR_*` and an output directory to
   `bin/build-pwa-icons` and run it. This writes `icon-192`, `icon-512`,
   `icon-maskable-512` and `apple-touch-icon-180` under
   `static/icons/<dir>/`.
2. Add a favicon with the same tile fill.
3. Add a `PWAEnvironmentIdentity` constant with the new `icon_static_dir`,
   `tile_color`, `favicon` and names. Keep `background_color` and
   `theme_color` at `LAUNCH_BACKGROUND`. Teach `from_settings()` to return
   it.
4. Add the environment to `ENVIRONMENTS` in
   `tests/public/test_pwa_launch_parity.py`, and to the tile-colour test in
   `tests/public/test_site_environment.py`.

## Testing a launch

Automated: `uv run pytest tests/public/test_pwa_launch_parity.py` and
`npx vitest run tests/js/test_pwa_launch_gate.js`.

On a device, follow scenario P3b in
[`testing-scenarios.md`](testing-scenarios.md). Android caches the manifest
at install, so **uninstall and reinstall** after any change to the manifest
or the icons; a hashed icon URL lets an existing install pick up the change
on Chrome's next WebAPK update check, but that can take days. Record the
screen and step through the handoff frame by frame. Anything you can see
moving is a bug.
