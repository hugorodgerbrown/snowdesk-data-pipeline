A1 / D3

The unsent-bulletin-email lie — four audits running — is dead, on all 22 surfaces

SNOW-707, SNOW-875, SNOW-805

This series flagged the same underlying falsehood in the first audit (11 August) and every one since: Snowdesk told readers, in various forms, that it emails them when a bulletin changes. Nothing ever did. Last week's audit found SNOW-7 (the digest) newly cancelled for good, its blocker resolved by unrelated work, and SNOW-707 — the bug tracking the false claims, filed 21 August naming ten surfaces, cancelled 27 minutes later — reopened the same day. This week that reopening turned into the actual fix: SNOW-875 deleted the dead email-subscription machinery (both send functions, the unsubscribe tokens, two views, two routes, four templates); SNOW-805 dropped the Subscription table; SNOW-707's rescope swept the whole template tree with a grep rather than trusting the original list, and found 22 surfaces, not ten, including privacy.html:154's GDPR lawful-basis claim (a compliance defect, not marketing copy) and a live transactional email template. All 22 are now clean.

  • apps/public/templates/public/privacy.html:239 — Resend now correctly scoped to "the emails the account itself needs: your sign-in link, the message that verifies your address, a password reset..."

N2 (31 Aug)

The resort/weather link is no longer a silent manual step

SNOW-885

Flagged 31 August as "watch, don't fix yet": link_resort_locations was pulled from the deploy pipeline, leaving a resort added or re-geocoded afterwards with no weather panel until an operator remembered to run the command. SNOW-885 built the missing mechanism: a --check flag that names every geocoded, unlinked resort and exits non-zero, scheduled daily at 05:00 UTC, sharing the exact Resort.objects.unlinked() queryset the linker itself uses so the two definitions of "unlinked" cannot drift apart. Measured against the local fixture set on 2026-09-09: 0 geocoded-and-unlinked resorts — the detector exists for a state that has not happened yet, which is the point.

  • apps/locations/management/commands/link_resort_locations.py — --check, non-zero exit, scheduled 05:00 UTC daily
N3 (7 Sep audit)

SNOW-855

Consequences

Four things this week's work changes about the older tickets

Connections between this cycle's decisions and tickets written before them — visible from neither side alone.

A tracked finding can now disappear without being fixed or explained

SNOW-669, SNOW-674 and SNOW-678 were all cancelled on the same day, 7 September. SNOW-669 got a comment explaining exactly why the ticket could no longer be actioned as written, and the page audit that flagged it named by title. SNOW-674 and SNOW-678 got nothing — no comment, no linked decision doc, no "won't fix" reasoning anyone could point to later. The practical effect is identical to a page audit finding simply not being written down: the orphaned /examples/ pages and the missing regions index are exactly as true today as they were three audits ago, but nothing in Linear currently says so. A future audit that trusted ticket state instead of code — the one discipline this series exists to enforce — would report both as resolved.

/compare/ repeats the orphan pattern SNOW-668 was supposed to have generalised

Three audits running (downloads, then trips) shipped new surfaces with the reachability discipline designed in from the start, not retrofitted after this series caught a gap. This week that streak has an asterisk: /compare/ shipped reachable, then had its only inbound link deliberately removed four days later, in a commit whose own message admits the page is now unreachable. It is a smaller version of the same failure mode as SNOW-674/678 above — a page that is fine and a decision that is unrecorded — rather than a returned bug.

SNOW-937 answers "decide SNOW-7" with a different transport than every prior audit assumed

Every audit since 19 August has tracked the competitive cost of the unsent digest and recommended, in some form, deciding SNOW-7's fate. SNOW-7 is now permanently cancelled and will not be revived — but the underlying product need (tell someone when the bulletin they care about changes) is being rebuilt today as push notifications, not email, on the back of a real season of diff data rather than the two-line placeholder SNOW-7 carried since April. The recommendation this series should carry forward is no longer "decide SNOW-7"; it is "watch SNOW-937 ship, and check the delivered behaviour against docs/roadmap.md once it does."

An audit whose PR sat closed and unmerged for a week still drove three real tickets

The 7 September audit's PR (#828) was drafted, reviewed by nobody, and left closed unmerged for a week — yet its findings drove three real tickets (SNOW-669's closure, SNOW-855, SNOW-885) via Linear comments quoting it directly. That is a good outcome for those three findings and a real gap for the series as a whole: for a week, this repository's own history of what was found and when had a week-shaped hole in it, recoverable only by reading Linear comments that happened to cite an Artifact URL. Fixed today (14 September): the PR's author reopened and merged #828 retroactively once they noticed, so 2026-09-07 is now a real entry in this directory and the baseline chain above is unbroken again. Nothing about this audit's own findings needed correcting as a result — this run had already re-verified everything directly against the code rather than trusting the draft — but the masthead, README history table and several cross-references below were rewritten to treat 7 September as the real predecessor it always should have been, rather than framing this audit as absorbing two weeks at once.
