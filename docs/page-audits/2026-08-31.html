That is the same sentence flagged as D3 in the first two audits and folded into SNOW-7 last week — and it is now the one privacy claim this pass left provably false, sitting inside a document every other paragraph of which just got corrected around it.

A resort geocoded after this week gets no weather panel until someone remembers to run it — the exact shape of gap this series exists to catch, flagged here before it has had the chance to go stale.

N2

…but the link between a resort and its weather is now a manual step

watch, don't fix yet

link_resort_locations — the command that creates the ResortLocation a resort needs before it can show weather — was deliberately taken out of the deploy pipeline this week ("Take the resort-location bulk write out of the deploy," #758). That is a reasonable operational call on its own terms, but it changes the shape of the guarantee N1 just established: a resort added or re-geocoded after this week renders no weather panel until an operator remembers to run the command by hand. Nothing currently tests for a resort silently missing its link. Not a finding against working code — a note that the next audit should re-check whether this has already happened to a resort added this week.

Consequences

Three things this week's work changes about the older tickets

Connections between this cycle's decisions and tickets written before them — visible from neither side alone.

D3 doesn't need SNOW-7 built — it needs SNOW-7 split

D3 has been tracked as "folded into SNOW-7" since last week, on the reasoning that fixing the false claim and building the real digest are one piece of work. This week's legal pass proves that reasoning wrong in practice: SNOW-772–775 rewrote privacy.html extensively without touching line 245, almost certainly because the false Resend claim isn't in that ticket cluster's scope — it's parked inside a ticket about building an entire email pipeline. The fix is a one-line deletion or edit; it does not require SNOW-7 to ship. Splitting it out is the only way it stops being invisible to whichever ticket cluster touches privacy.html next.

The unsent-email gap is now three competitors deep

The 08-19 scan found AvalancheClarity had shipped push-on-new-bulletin alerts. 08-23 found it had also shipped cross-provider consolidation, across all three of Snowdesk's own provider geographies. This week's 08-30 scan adds a third product (Skida) built specifically around cross-provider normalisation, plus Regobs/Varsom shipping slope-angle layers. SNOW-7 remains Todo, unassigned to a cycle, while the market position it would have staked out keeps getting claimed by more parties in more ways.

SNOW-668's fix generalised — the discipline, not just the two pages

Downloads (N3) shipped this week without an orphan gap, unprompted by this audit. That is the first positive evidence that SNOW-705's nav-ownership doc and SNOW-668's "adding one section is adding one <a> to this list" comment changed how new account surfaces get built, not just how the two already-caught ones got patched. Worth watching on the next page that touches the account area, to see whether it holds a third time.
