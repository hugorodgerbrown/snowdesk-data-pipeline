Consequences

Four things this week's work changes about the older tickets

Connections between this cycle's decisions and tickets written before them — visible from neither side alone.

SNOW-669 is now obsolete, not open

SNOW-669, "give the public observations stream a way in," has sat Ready for dev since 2026-08-11, asking for exactly one thing: a link somewhere to /observations/. That page no longer exists — SNOW-804 deleted it and redirects to the map's reports sheet instead. Building what SNOW-669 asks for is now impossible as written; the ticket should be closed as obsolete, not left open waiting for work that would target a page nobody can reach because it isn't there to reach.

A canceled bug ticket got half-fixed by accident, and the surviving half just grew

SNOW-707, "the product promises bulletin alerts it never sends," named thirteen surfaces on 2026-08-21 and was canceled twenty-seven minutes later. Five of its "product surfaces" — subscribe_form.html, hub.html, subscribe_success_added.html, the unsubscribe copy, the account_subscribed email — are gone this week, deleted as a side effect of SNOW-795's unrelated IA rewrite, not because anyone acted on the bug report. Its "legal pages" half — privacy.html, terms_of_service.html §7, the sharpest examples the ticket named — is untouched. And the ticket's own list is now incomplete in the other direction: home.html's meta description and the homepage's register CTA weren't on SNOW-707's original thirteen and still make the same claim. A ticket closed as Canceled is not being tracked by anything; reopening it, rescoped to the four surfaces that remain, is the only way this stops being invisible to whoever next touches the legal pages.

SNOW-7's stated blocker is resolved — by different work, under a different ticket

SNOW-7's own description names SNOW-665 ("unify Subscription and Favourite into a single places model") as what it's blocked on, "which settles what a place is." SNOW-665 was canceled on 2026-08-23. This week, SNOW-802 did exactly what SNOW-665 asked — Favourite is now the one saved-place model, with a region-pin kind absorbing everything Subscription recorded — as part of the unrelated SNOW-795 rewrite. SNOW-7's description is now stale in a way that matters: the open question it names as blocking it has an answer in the codebase today. Building the digest no longer waits on a data-model decision; it waits on being scheduled.

Last week's "watch" item left a trace this week's page-rebuild didn't catch

Last audit flagged link_resort_locations as a manual step with nothing to notice a resort silently missing its weather link (N2 there). Nothing changed operationally this week — still no monitoring, still manual — but resort.html was rebuilt from scratch this week (SNOW-807) with full context on how a resort's locations get linked, and its new meta description still overclaims three named forecast tiers for a resort that, via exactly that manual command, may have only one anonymous one (N3 above). The gap didn't just sit still; it grew a second symptom in a page written the same week the first one was flagged.
