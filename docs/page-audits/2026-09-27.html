Consequences

What this week's shape changes about the older tickets

Connections between this cycle's decisions and tickets written before them — visible from neither side alone.

Last week's counter-example didn't survive the week that named it

The 20 September audit held up SNOW-909's terrain work as "the first big feature in this run of audits that got the hard parts right from the start." Four days later, SNOW-1019 took the crux rings and fall-line arrows off the map, and SNOW-1017 had already taken the six slope colours off it the day before that. None of this makes last week's praise wrong — the underlying terrain data, the unknown-state handling and the bulletin-overlap discipline this audit checked are all still exactly as described, just presented differently — but it is a reminder that "shipped whole" is a snapshot, not a property, on a codebase iterating this fast. The one genuinely new gap the iteration introduced — the Trip page not following the map's redesign — is exactly the kind of split a reachability-focused audit exists to catch, and it would have been invisible to anyone reading the decision doc alone, since the doc states the gap in passing without flagging it as one.

A ticket can close an open question by superseding it without ever answering it

SNOW-674 and SNOW-678 have taught this series to watch for a Canceled ticket with no explanatory comment. SNOW-977's closure is the same failure in a quieter disguise: it resolved as Duplicate of a ticket that shipped (SNOW-1006, Done), which reads as progress rather than abandonment. But Done and Duplicate both mean the same thing for an open question the ticket asked and the superseding ticket never mentions: nobody answered it, and the tracker now shows green. The public-explainer series has since grown to five pages under that same unanswered question, which makes the ticket hygiene failure more expensive with every page it accumulates, not less.

A second product surface has now shipped with a "discoverable only from outside our own site" shape, and nothing says whether that is deliberate

The OAuth/MCP work and the public-explainer series are different in almost every way — one is infrastructure for an external client, the other is reader-facing prose — but both now share the same structure: real, working, documented pages that a visitor arriving from snowdesk-data-pipeline's own front door cannot reach by clicking anything. For the explainers this is plausibly still in progress (SNOW-977's open question, however poorly it was closed, at least existed). For the OAuth/MCP surface no ticket or doc raises the discovery question at all — the account-settings copy's own reasoning ("an empty section would be a heading explaining a feature from inside the settings page") argues against putting it there, but does not say where it should go instead.

SNOW-937 is now old enough that "paused on purpose" and "quietly dropped" are equally likely reads

Last week's recommendation asked for one sentence confirming whether the alerting rebuild was a deliberate pause. That sentence still has not been written — the ticket has never had a comment, in over two weeks of being "In Progress." This week the maintainer's attention went to two substantial, unrelated builds (the route rails, the OAuth server), which is a second week of evidence for "deliberately reprioritised" — but the absence of a single line saying so is now the more notable fact than anything happening in the ticket itself.

Recommendation

What I'd do next

First, decide the public-explainer reachability question for real, now that closing SNOW-977 as a duplicate has made it look decided when it isn't. Five pages deep with zero live links is a bigger problem than the one page this series flagged last week, and the ticket that could have settled it didn't.

Then say, in one place, whether the OAuth/MCP surface is meant to be discoverable from Snowdesk's own site or exclusively via Claude's connector directory. Either answer is defensible; the absence of one means this audit has to keep re-checking a feature that may already be working exactly as intended.

Then decide whether the Trip page should follow the map's move to legs, or whether the slope-coloured line is the Trip page's deliberate final form — and write whichever it is into legs-not-slope-classes-on-the-map.md or a follow-up doc, so the next audit isn't the only place this split is recorded.

Then confirm whether SNOW-937 is paused on purpose — now overdue by a second week, and the ticket's total silence is the more remarkable fact than anything currently happening around it.

Cheapest and oldest: SNOW-674, SNOW-678, and /compare/'s footer link. Three audits running on the first two, one sentence each would close the gap; the third has never had a ticket at all despite the decision already being made in a test rename.
