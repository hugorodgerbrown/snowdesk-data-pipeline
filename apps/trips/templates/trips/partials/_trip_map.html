{% load i18n static components %} {% comment %} trips/partials/_trip_map.html — the trip's map canvas and its payload. One MapLibre canvas showing the route as a line with a marker where the group meets, and below it, in the same card, the route's name, its figures and its elevation profile. Drawn by static/js/trip_map.js from an INLINE payload rather than a fetched one: the page already holds every byte of it, it is small, and a public share page that had to make a second request to draw its own map would show a recipient nothing at all while that request was in flight. THE MODULES LOAD BEFORE trip_map.js AND THE ORDER IS LOAD-BEARING. Deferred scripts run in document order, so `self.pwaElevationProfileCore`, `self.pwaRouteMarkersCore`, `self.pwaRouteCursorMapCore` and `self.pwaStrings` all exist by the time trip_map.js's top level runs. Each is reused UNCHANGED from the map page — they publish frozen globals and own no map state. The
has an explicit height rather than an aspect ratio: MapLibre measures its container on construction, and a container whose height is still resolving gives a canvas of zero pixels that never repaints. SNOW-840 CHANGED WHERE THE PROFILE SITS AND WHAT SURROUNDS IT. This comment used to say the profile sat "underneath" the map, and that was literally true: a bare unframed SVG bleeding to the full page width under the "View on the map" button, while the figures that give its y-axis a meaning were a line in _trip_summary.html, above the map and a card away. The map page's route popup has always drawn the two as one object — the name, the figures, the profile, then the profile's range — and that is the right grouping for the same reason it is there: the drawing is a PICTURE OF THOSE NUMBERS. SNOW-848 PULLED THE CANVAS INTO THAT CARD TOO, so the whole route — the map, its figures, its profile and the way out to the real map — is one object on the page rather than a canvas, a loose button and a card underneath it. The map takes the card's top edge with no padding and a bottom border; "View on the map" moves into a footer strip, as an accent link rather than an outlined button, because a footer strip is where this design puts a card's one secondary exit. SNOW-1216 GAVE THE CARD A TITLE LINE AND THE MAP'S PROFILE. The card used to have no title ("the page's heading is already the trip's name"), but the heading names the TRIP and the card is the ROUTE, which has a name of its own; and the profile was trip_map.js's single-colour area, a different drawing of the same track from the one the map's route panel draws. It is now that drawing (includes/_route_profile.html), with a scrub cursor whose point trip_map.js draws on the canvas above.
