{% load i18n static components %} {% comment %} trips/partials/_trip_map.html — the trip's map canvas and its payload. One MapLibre canvas showing the route as a line with a marker where the group meets, and below it a CARD holding the route's figures, its elevation profile and the profile's own scale. Drawn by static/js/trip_map.js from an INLINE payload rather than a fetched one: the page already holds every byte of it, it is small, and a public share page that had to make a second request to draw its own map would show a recipient nothing at all while that request was in flight. THREE MODULES LOAD BEFORE trip_map.js AND THE ORDER IS LOAD-BEARING. Deferred scripts run in document order, so `self.pwaElevationProfileCore`, `self.pwaRouteMarkersCore` and `self.pwaStrings` all exist by the time trip_map.js's top level runs. The first two are reused UNCHANGED from the map page — they already publish frozen globals, own no map state, and the elevation profile a trip draws is the same picture a route popup draws of the same geometry. The
has an explicit height rather than an aspect ratio: MapLibre measures its container on construction, and a container whose height is still resolving gives a canvas of zero pixels that never repaints. SNOW-840 CHANGED WHERE THE PROFILE SITS AND WHAT SURROUNDS IT. This comment used to say the profile sat "underneath" the map, and that was literally true: a bare unframed SVG bleeding to the full page width under the "View on the map" button, while the figures that give its y-axis a meaning were a line in _trip_summary.html, above the map and a card away. The map page's route popup has always drawn the two as one object — the name, the figures, the profile, then the profile's range — and that is the right grouping for the same reason it is there: the drawing is a PICTURE OF THOSE NUMBERS. Both now live in one card component, which is also what stops the SVG sprawling to the full page width. There is no title line in this card, unlike the popup's. The popup is a free-floating object on a map and has to say which route it is about; this card is inside a page whose heading is already the trip's name.
