The four things a person reads off a message before deciding whether they are going: the day, the time, where the group meets, and how far and how much climbing the route carries. Rendered above the map on every trip surface — the organiser's object page and the public share page — so a recipient who never scrolls has still been told the whole plan. The meeting point is a COORDINATE PAIR, not a place name. The Location it comes from is minted for this trip alone and carries no name, deliberately (naming a place is a curation act — see apps/trips/services/trips.py), so inventing a label here would be inventing a fact. Six decimal places is roughly 0.1 m, which is well inside GPS noise but is what a map app expects pasted into its search box. ASCENT AND DESCENT ARE NULLABLE AND THE NULL IS MEANINGFUL. A route with no elevation data anywhere carries null, and Trip's own docstring is explicit that "we don't know" and "flat" are different facts — rendering the second for the first would be a safety-relevant lie about terrain someone is planning to ski. So a trip with no vertical data shows its distance alone rather than "0m ↑". Each branch is a whole phrase rather than assembled fragments, so a locale can order it freely — the same rule routes/partials/_route.html's meta line follows, and for the same reason. A trip's figures ARE its route's figures — the geometry is a snapshot of one — so a user who meets the same numbers in the routes panel, in the map popup and here should not meet three spellings of one measurement. Width is not the argument on this surface.
