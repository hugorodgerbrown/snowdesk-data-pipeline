{% load i18n components %} {% comment %} trips/partials/_trip_bulletin.html — where this day's line meets this day's bulletin (SNOW-839). The one thing on a trip page that changes twice a day. Everything else is the snapshot the organiser shared; this is read fresh on every view and stored nowhere, because a cached intersection would be held offline by the service worker under a date it no longer belongs to. WHAT THIS IS NOT. It is not a score, not a verdict and not a recommendation, and the copy is written so it cannot be read as one. A number would suppress everything it did not weigh, invisibly — and ``docs/decisions/location-first-information-model.md`` already draws that line: highlight, never suppress, which is "the line between helping someone read a bulletin and deciding for them, and it is what our liability disclaimer rests on". So every row states a fact about the TRACK ("1.4 km of your line, on N and NE, between 2200 and 2800 m") and names the problem the forecaster put there. The deciding is the reader's, with the bulletin this panel links them to. ONE BLOCK PER REGION, longest stretch first. A track over a ridge is in two micro-regions, and on a border it is two PROVIDERS with two readings of the same day — so the panel shows both rather than picking one, and names each. A region with no bulletin for the day is still listed: a reader whose route leaves the forecast needs to know it did.
