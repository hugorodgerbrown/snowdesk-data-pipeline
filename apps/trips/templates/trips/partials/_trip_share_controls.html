{% load i18n components %} {% comment %} trips/partials/_trip_share_controls.html — the organiser's Share and Revoke (SNOW-821). Two buttons and no form. trips:share_create and trips:share_revoke answer JSON to a plain fetch(), because the minted URL goes to the native share sheet (window.pwaShare, shared unchanged with the bulletin page and the routes panel) rather than into the page. BOTH CONTROLS ARE ALWAYS RENDERED, and Revoke is disabled rather than absent when there is no live link. A control that appears and disappears as state changes reads as a bug on a page a user visits twice; a disabled one says "this is the thing you would press, and there is nothing to press it on". The site's rule anyway: show controls, don't hide them. SHARING AGAIN ROTATES THE LINK. That is stated in the copy under the buttons rather than left for a user to discover, because it is the one behaviour here with a consequence somebody else feels — a link already sent to a group chat stops working. It is also the only revoke-and-reshare an organiser has, so it earns its sentence. The uuid rides on each button (`data-trip-share`, `data-trip-share-revoke`) so the delegated handler needs no closure over the rendered page — the same contract the route row's own Share carries. `{% templatetag openblock %} button_classes {% templatetag closeblock %}` directly rather than includes/_button.html: that partial renders the label and nothing else, and these two carry data attributes a delegated handler reads. The class STRING is still the design system's, which is the part that must not be written out by hand. Context: trip : Trip — the trip whose link these controls manage. {% endcomment %}
