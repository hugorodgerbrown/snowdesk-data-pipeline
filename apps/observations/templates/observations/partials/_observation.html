{% load i18n map_focus %} {% comment %} observations/partials/_observation.html — One field-observation row (SNOW-658). Rendered by apps.observations.views.observation_list, one per row, inside the map's field-observation panel. The row is includes/_ugc_panel_row.html — the one anatomy Hugo's design gives all three UGC panels. This panel uses the fewest of its slots: no rule (it has no per-row identity to carry), no value (a timestamp is not a measured quantity), and one action. Remove is that action — a trash icon control (observations/partials/_observation_row_actions.html), in the same place it sits on the other two panels. It was an inline link-styled button, then for one day a "…" menu item; the design has neither. The row keeps its own id, so the Remove form's ``hx-target="#observation-"`` / ``hx-swap="outerHTML"`` still swaps out exactly this row on the empty body the delete endpoint returns, and nothing on the page has to know which row was clicked. The label is not a link and not renameable: an observation has no page of its own to navigate to, and nothing about it is editable after the fact. On the map it IS a control, and the one thing it does is frame the report — Hugo: "For routes, resorts, and observations, clicking on the name of an item should zoom in to it." Pressing it flies to where the report was made and closes the panel. The coordinates come from the OWNER'S OWN row, which is the only place they exist at full precision: ``apps.public.api.community_reports_geojson`` rounds every pin to 3 dp (~100 m) and strips the identity before the layer ever sees it, and that anonymisation is not something a convenience gesture gets to unpick. This partial is rendered by ``observation_list``, which is scoped to ``for_user`` — so the exact coordinate is only ever put in front of the person who chose it. The pin the camera lands beside is the rounded one, up to ~100 m off; at this scale that is inside the marker.
