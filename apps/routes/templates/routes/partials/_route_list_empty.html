{% load i18n %} {% comment %} routes/partials/_route_list_empty.html — the routes empty clause (SNOW-721). Rendered by BOTH list variants — _route_list.html and _route_list_map.html — from inside their own ``{% if not routes %}`` guard. It has its own file because the two must say the same thing: the clause was duplicated verbatim in both until SNOW-721, and a second edit to one of them was exactly the drift the design system's reuse-first rule exists to stop. WHY IT NAMES DEVICES. "You have no saved routes yet." states a fact and stops. A user who has never exported a GPX cannot act on it: the panel's CTA opens a native file picker onto a folder holding no .gpx, and nothing on the surface says where one comes from. So the copy says what to upload and names the class of device that produces one, with two vendors as examples rather than as an endorsement or a supported-hardware list. Two sentences, two msgids. They are independent statements — what to upload, and where such a file comes from — so a locale can render either without reassembling the other, and a later edit to one does not invalidate the translation of both. The strings belong here and not in static/js/routes.js. The panel's failed-load line is deliberately a separate string (see the note in public/partials/_routes_surface.html) because "you have no routes" and "your routes couldn't be loaded" are different claims about a user's own data. This one must not drift into the JS strings template, where `tox -e i18n-lint` would be the only thing between it and shipping as English to every locale. Carries data-testid="route-list-empty" — the hook both variants' tests assert on, unchanged from when the clause was inline in each. A plain link to routes:example, which reloads the map on the example's day with the walkthrough.
