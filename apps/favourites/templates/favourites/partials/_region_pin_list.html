{% comment %} favourites/partials/_region_pin_list.html — the user's pinned regions, as data (SNOW-814). Rendered by apps.favourites.views.region_pin_list and swapped by static/js/map_region_panel.js into a hidden host in the ribbon (#region-pin-rows). Nothing draws it: the module reads each item's ``data-pinned-region`` id and publishes them as window.pwaPinnedRegions, which search lists before anything is typed and the pin roundel reads its state from. WHY IT IS ONLY IDS. Until SNOW-1173 this list was drawn, as the last section of the region + date panel the #region-readout chip disclosed, so each item was a full UGC row: a name that framed the region and a filled star that unpinned it. SNOW-1173 retired the panel and left the rows rendering into a hidden host, where their controls could never be pressed — a star nobody could find (Hugo, 4 Nov 2026: "Which is the region unpin icon, I can't find it" / "Strip it"). A region is unpinned from the filled star roundel in its sheet's header (_map_region_pin_control.html, proxied by _region_sheet_peek.html), so the list keeps only what is read from it. The name rides along as text, for whoever inspects the response. Context: region_pins : list[Favourite] — the requesting user's region pins. {% endcomment %}
