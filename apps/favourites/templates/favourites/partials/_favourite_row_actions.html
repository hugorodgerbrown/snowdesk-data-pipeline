See _favourite_row_menu_items.html. WHAT THE MENU'S IDS ARE, AND WHY THEY ARE PER-ROW. A panel lists many pins and each renders this partial, so `trigger_id`/`menu_id` are keyed on the favourite's own uuid — the trigger's `aria-controls` has to name one element. static/js/overflow_menu.js itself never reads them (it is scoped by `closest()`, not `getElementById`); they exist for ARIA correctness. That script is loaded once by the map page (apps/public/templates/public/home.html), which since SNOW-803 is the only surface any of these rows render on. The trigger's own aria-label names the row for the same reason the items' do: "More actions" alone names nothing with a list of rows on screen. It interpolates ``label`` — includes/_ugc_panel_row.html's own parameter, in scope here — rather than ``favourite.name``, so an unnamed pin reads as "Actions for Unnamed pin" rather than "Actions for ". ``row_target`` rather than a hardcoded ``#favourite-``: the row's id is _favourite.html's to decide, and an actions partial that rebuilt the same string from the uuid would be a second place to change if it ever does. The one caller passes ``#``; this file just passes on whatever it was handed, to the menu items that own the Delete form. WHICH SURFACE RENDERS THIS (corrected by SNOW-886).
