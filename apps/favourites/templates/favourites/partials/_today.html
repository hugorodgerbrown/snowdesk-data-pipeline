Each region is one compact group: its name is the heading, with today's EAWS level on the right, and the resorts under it are bare rows with today's weather on the right, so the right edge always holds the reading. No subtext: no trend since yesterday, no "not pinned", no icon tile saying what kind of place a row is — the grouping already says it. A region with no bulletin shows the muted no-rating tile in the level's place, so the column never reads as "still loading". The tile is aria-hidden, so its level (or "No bulletin today") is said to a screen reader in words. These rows are the panel's own, not includes/_place_link_row.html: they keep that partial's contract with static/js/map_panel_trail.js — ``data-panel-open`` / ``data-panel-id`` (and ``data-resort-slug``) on a real link to the place's page — so a row opens the place's sheet on the map, and the root's ``data-panel-key`` / ``data-panel-label`` name the back pill that returns here. A borrowed forecast says where it is from (includes/_forecast_source.html), as docs/decisions/snowdesk-decides-where-a-forecast-is-fetched.md asks of every borrowing surface. A resort normally reads its own pin's forecast, and then the line would only repeat the resort's name, so it is shown only when the point is somewhere else.
