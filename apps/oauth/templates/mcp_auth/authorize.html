{% extends "includes/_status_page.html" %} {% comment %} apps/oauth/templates/mcp_auth/authorize.html — the OAuth consent page (SNOW-1035, SNOW-1193). Snowdesk's copy of mcp-auth's consent template, rendered by its ``ConsentView`` once the client, redirect URI and every authorize parameter have been checked. Names the app, the host a code will be sent to (the fact a user can verify — the name is whatever the app called itself), the account it will act as, and what access means: reading avalanche data, nothing else. ``redirect_is_loopback`` adds a warning: the code goes to a program on this computer (Claude Code and similar), not to a named web service, so the host line alone proves nothing. Two forms. "Use another account" posts to mcp-auth's switch-account view, which signs out and comes back here through sign-in. Allow and Cancel are one CSRF-protected POST back to this URL; mcp-auth tells them apart by the ``allow`` field, and its hidden fields carry the authorize parameters so the POST re-runs every check. The answer is mcp_auth/returning.html, not a 302, because the site CSP's ``form-action 'self'`` would block the redirect (``MCP_AUTH["CONSENT_RETURN"] = "page"``). ``error`` set means the request itself was bad (an unknown client, a callback it did not register); there is no form to show.
