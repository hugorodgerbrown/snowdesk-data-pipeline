{% extends "public/base.html" %} {% comment %} apps/public/templates/public/resort.html — Public resort detail page (SNOW-504). Gives a Resort its own indexable URL (``/resorts//``), rendered by ``apps.public.views.resort_detail``. Cross-linked from the map's resort-pin popup, whose CTA reads "View resort →". A ROUTER TO THE TWO DOCUMENTS (SNOW-807, docs/decisions/two-documents-and- a-map.md). The page is kept because people search "Verbier avalanche", not "CH-4115" — but it is not a third document, and it renders nothing that belongs to one. Someone landing here from a search engine gets to the bulletin or a forecast in one tap. Sections, top to bottom: 1. Resort name (+ alternative/marketing name, when set), canton, and parent region name, then the curated "why it matters" line (SNOW-542) via the shared ``public/partials/_resort_why_it_matters.html`` partial, which owns its own blank state, then the curated facts block (SNOW-695) via ``public/partials/_resort_facts.html`` — operator, website, lifts, runs, piste, elevation range, season and notes, each cell omitted when unset and the whole block omitted when all are. The resort's own. 2. The danger area — ONE link to the parent region's evergreen bulletin, carrying today's ``.danger-tile`` chip (or the no-bulletin note) and the "View bulletin →" label. It was a chip beside a separate button; the whole area is the link now, and tests/e2e/test_resort_page.py clicks ``[data-testid="resort-danger"] a`` — keep exactly one. 3. The favourite/unfavourite control (``favourites/partials/_resort_favourite_button.html``). 4. Forecasts — a plain list of the resort's curated locations, each a link to its own weather page (``/weather//``), with the role and elevation that tell village from summit. No weather data is read here: SNOW-761 drew one block per location and SNOW-783 trimmed it to the day; this removes the rest. A resort with no curated locations renders no section at all — ``link_resort_locations`` is a manual operator step, so that state is normal. 5. Observations — ONE link to the map with the reports sheet open, flown to this resort (``?panel=reports&resort=``). The point-local counts SNOW-508 rendered here were a filtered view of map data. Resorts with ``needs_review=True`` or null coordinates still render here — only the map-anchor affordance is skipped, and this page has none. Context expected (built by ``apps.public.views.resort_detail``): resort — regions.Resort instance. region — regions.MicroRegion instance (resort.region, select_related region). region_id — str: region.region_id. day_rating — bulletins.RegionDayRating for today, or None. target_date — datetime.date: today. bulletin_url — str: the region's evergreen bulletin URL. favourited — bool. favourite_uuid — str: "" when not favourited. can_favourite — bool. Doubles as the "is signed in" signal read by the why-it-matters partial. is_staff — bool: switches the why-it-matters blank state to a curation hint (SNOW-542). signin_url — str: accounts:sign_in URL. locations — list[dict]: the resort's curated locations (label, elevation_m, role_label, url, testid), primary first.
