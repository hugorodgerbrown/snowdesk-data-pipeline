Sections, top to bottom: 1. Resort name (+ alternative/marketing name, when set), canton, and parent region name, then the curated "why it matters" line (SNOW-542) via the shared ``public/partials/_resort_why_it_matters.html`` partial, which owns its own blank state, then the curated facts block (SNOW-695) via ``public/partials/_resort_facts.html`` — operator, website, lifts, runs, piste, elevation range, season and notes, each cell omitted when unset and the whole block omitted when all are. 2. Today's danger chip — reuses the ``.danger-tile`` component from ``_region_tooltip.html`` — alongside a "View bulletin →" link to the parent region's evergreen bulletin page. 3. The favourite/unfavourite control (``favourites/partials/_resort_favourite_button.html``). 4. Field-observation counts (SNOW-508) — point-local, scoped to ``settings.FIELD_OBSERVATION_RADIUS_KM`` of the resort's own coordinates, falling back to the region-wide count (the ``bulletin.html`` pattern) when the resort has no coordinates. Resorts with ``needs_review=True`` or null coordinates still render here — only the map-anchor affordance is skipped, and this page has none.
