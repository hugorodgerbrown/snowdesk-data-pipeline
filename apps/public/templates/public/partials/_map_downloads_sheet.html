The surface that answers "what have I stored offline, and what is it costing me". Opened from ``#map-custom-download-control`` (the bottom-right roundel — public/partials/_map_custom_download_control.html) and driven by static/js/map_downloads_manager.js. SNOW-588 through SNOW-632 reached this sheet only via a ``[data-menu-action="manage-downloads"]`` row buried in the layers menu, while the roundel opened a DIFFERENT surface (the "Download a custom area" framing overlay) directly. SNOW-634 collapses the two: the roundel now opens THIS sheet, the menu row is gone, and "Download a custom area" became an action INSIDE the sheet instead — the ``[data-downloads-add]`` trigger, handled by map_downloads_manager.js's delegated click listener (offline: disabled and relabelled — SNOW-637; online: hide this sheet and call ``window.pwaCustomAreaDownload.openFraming()``, map.js's own bridge for it). SNOW-645 review supersedes SNOW-641's running order (list, then trigger, then a bordered budget block at the foot): the budget moved back to the TOP, folded into the header block itself, because Hugo's design reads it as part of "what this sheet is" rather than a footnote below the list — the opposite conclusion SNOW-641 drew, and worth noting so a future reader does not assume SNOW-641's reasoning still holds. Nothing here is positional as far as the JS is concerned: every element is addressed by data-attribute, never by index or sibling relationship, so reordering never needs a JS change. It lives on the map, rather than under account settings, for two reasons. Downloading happens here, so managing downloads belongs here; and the list has to name each area, which on the map is free — ``FEATURE_BY_REGION_ID`` already holds every region's name from the SW-cached ``regions.geojson``, so the names resolve offline, which is exactly when storage pressure is felt. An account page would also imply the list follows the user between devices, and it emphatically does not: Cache Storage is per-browser, so both the downloads and the budget are **device-local**.
