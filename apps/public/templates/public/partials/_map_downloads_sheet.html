{% load i18n static %} {% comment %} public/partials/_map_downloads_sheet.html — "Manage downloads" sheet (SNOW-588). The surface that answers "what have I stored offline, and what is it costing me". Opened from the ``[data-menu-action="manage-downloads"]`` row in the layers menu (public/partials/_map_embed.html) and driven by static/js/map_downloads_manager.js. It lives on the map, rather than under account settings, for two reasons. Downloading happens here, so managing downloads belongs here; and the list has to name each area, which on the map is free — ``FEATURE_BY_REGION_ID`` already holds every region's name from the SW-cached ``regions.geojson``, so the names resolve offline, which is exactly when storage pressure is felt. An account page would also imply the list follows the user between devices, and it emphatically does not: Cache Storage is per-browser, so both the downloads and the budget are **device-local**. Every string below is written to say so. Structure mirrors _favourites_surface.html: the shared sheet primitive (includes/_overlay_sheet.html) as an empty container, plus server-rendered ``
