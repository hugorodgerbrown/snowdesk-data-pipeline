{% load i18n static %} {% comment %} public/partials/_routes_surface.html — saved-routes sheet + JS (SNOW-686). The fourth UGC surface, built to the shape SNOW-634 set for downloads and SNOW-658 generalised across favourites and field observations: its own roundel (#route-add-btn, public/partials/_map_embed.html), its own sheet, and rows rendered server-side and swapped in over HTMX. Mirrors _favourites_surface.html throughout — that file is the reference implementation, and the differences below are all deliberate. Included from home.html only when ``routes_visible`` (the ``routes`` waffle flag) is active, so nothing here reaches the DOM for a user the feature is not yet open to. See apps.public.views._routes_context for why the flag gates a whole surface rather than one control. Three shared modules are loaded once each by home.html before this partial — none is repeated here: htmx.min.js the panel's row list and each row's Remove form. map_sheet.js the sheet controller, failure toast and overlay registration this surface shares with the other three. inline_rename.js routes.js drives window.pwaInlineRename for the row's in-place rename, unchanged and unforked. WHAT THIS SURFACE DOES NOT HAVE, and why each absence is deliberate: No "Display on the map" switch. There is no routes map layer yet — SNOW-687 adds the MapLibre line and the overlay bridge — so includes/_ugc_panel.html is included WITHOUT a ``toggle_id`` and renders no switch. A switch wired to nothing is a worse lie than an absent one; see that partial's own note on the parameter. No place-picker. A route's geometry comes out of the uploaded file, so there is nothing to place on the map and window.PlacePicker is never armed. This is the biggest single difference from the favourites surface. No mutation queue. Upload is ONLINE-ONLY and posts straight to routes:create rather than through window.pwaMutationQueue: the queue persists JSON bodies in IndexedDB and a multipart file is a different shape, so making an upload replayable is real scope of its own. SNOW-504's resort-favourite toggle is the precedent for a UGC action that is deliberately online-only. Rename and delete are online-only too, matching every other panel's edits. No offline cache sidecar. _favourite_list_map.html carries ``roster_payload`` for favourites_offline.js; caching routes for offline reads arrives with the layer in SNOW-687, since until something draws a route there is nothing an offline reader could do with one.
