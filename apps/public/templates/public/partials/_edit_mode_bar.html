{% load i18n components %} {% comment %} public/partials/_edit_mode_bar.html — switch and close for the in-map editors (SNOW-755). Both editor panels (edit_resorts_panel.html, edit_locations_panel.html) render this immediately above their own heading. It answers the two questions neither panel could: how do I get to the other editor, and how do I get out of edit mode at all. Before this, the only ways out were hand-editing the URL or clicking the wordmark — neither of which is an affordance, because neither is visible. Extracted rather than inlined twice: both headers already had the identical shape, and two panels needing the same new control is the case the design system's "reuse first, extract second" rule names. Parameters (passed via {% include … with … %}): active (string) — "resorts" or "locations": which editor is open. Marks that item aria-current="page" and gives it the filled state; the other becomes the link out. PLAIN LINKS, NOT JS — deliberately. Edit mode is query-string state (apps/public/views.py::_edit_target), so switching editors is a link to ?edit= and closing is a link to the bare home URL. A fetch or a handler would have to reason about the panel's own JS state — a half-placed pin, a request in flight — where a navigation simply discards it, which is what "close" means. It also works before the panel's script has loaded, and with it broken. Close goes to "/" rather than stripping only the ``edit`` parameter. That is exactly what clicking the wordmark already does; the point of this control is that it is discoverable, not that it is different.
