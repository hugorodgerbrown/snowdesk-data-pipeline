{% load i18n snowdesk_time %} {% comment %} apps/public/templates/public/partials/_resort_facts.html — Resort facts block (SNOW-695). The curated ``Resort`` columns the detail page stored but never rendered: operator, website, lifts, runs, piste length, elevation range, typical season and notes. ``kind`` and ``tier`` are deliberately absent — they are staff-facing curation fields, not reader-facing facts. Two deliberate differences from ``_resort_meta_row.html``, which renders the same underlying fields in the map's resort popup: * That partial never omits a blank field — it renders a dashed-box placeholder so missing curation stays visible to staff. This block does the opposite: an unset field renders nothing at all, and the whole block is omitted when every field is unset. The popup is a curation surface; this is a public detail page, and it follows the same no-empty-state discipline as the point-forecast section above it. * The label primitive here is the shared ``includes/_meta_cell.html``, reused rather than re-inlined per design-system rule 1. Numeric fields test ``is not None`` rather than truthiness, so a genuine zero (no lifts, no piste) renders as the fact it is instead of vanishing. Elevation and season each compose two nullable columns into one cell and degrade to a one-sided "from"/"to" reading when only one end is curated.
