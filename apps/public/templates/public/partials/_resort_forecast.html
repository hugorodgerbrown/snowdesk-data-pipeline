{% load i18n humanize weather_icons %} {% comment %} public/partials/_resort_forecast.html — the resort page's "Forecast" section (SNOW-1157): a seven-day strip for each of the resort's Base, Mid and Summit points, one point shown at a time, chosen by a chip. Drawn to Hugo's approved board (WeatherToday / WeatherWinter, the Mobile tile layout). It replaced the SNOW-807/SNOW-1125 list of location links, each with a one-day row. THE CHIPS ARE RADIOS, AND THERE IS NO JAVASCRIPT. One visually hidden radio per point, all of them FIRST in the card, then the chip group, then one pane per point. ``:checked ~`` reaches every later sibling, so each radio can style its own chip and reveal its own pane — rules written by hand in src/css/main.css ("Resort forecast points"), paired on ``data-point`` on both ends, because ``peer-checked:`` cannot name WHICH later sibling, so a stack of panes would show the checked one and every one after it (the same trap the weather day picker documents in docs/decisions/weather-day-picker-is-a-selector-not-navigation.md). The first point — Base when there is one — is checked on load, so the page reads correctly with no CSS state at all. Every pane's default is ``display: none``; an unmatched index shows nothing rather than all. A resort with one point still gets its one chip: it names the altitude the strip describes, which a bare strip would not. THE TILES. Today first and wider (``1.9fr`` beside six ``1fr`` from ``sm``; a full-width row above the six on a phone), with a ``
`` of Max / Min / New snow. The other six are unlabelled: weekday, icon, high (bold), low and new snow in mono. Zero new snow reads "0 cm", never blank — on an avalanche page none is a statement; a value Open-Meteo dropped reads "—". Each tile is ``role="group"`` with a spoken summary ("Today, Wednesday, snow, high -2°, low -7°, 0 cm new snow"), so the icon is decorative. A week shorter than seven days renders what it has. These are NOT the weather page's day-picker cells: those are labels for radios with a selection marker; these are inert summaries, and each one links nowhere — the pane's one link is to the full week. UNDER THE PANES (Hugo, 27 Oct 2026) the point chips, as one segmented row — above the week they took two rows before any weather — then the shown point's "View hourly forecast →" to its ``/weather//``, one link per point revealed by its radio as its pane is. The source and fetch time are the section's eyebrow, "Weather • Open-Meteo HH:MM" (``forecast_updated_at``), not a footer line. Today's tile names the point it shows ("Base 1,494 m"), since the chips are now below it, and in the map (``in_map``) it marks the end of the phone sheet's HALF (``data-sheet-half="fit"``). A point with no row today says "No forecast yet." and keeps the link. WITH NO FORECAST AT ALL — no point has a row for the day — the card goes and one line stands in for the section: "No forecast available for 18 May 2026" (SNOW-1205). A point with no row beside one that has a row still gets its chip and "No forecast yet.".
