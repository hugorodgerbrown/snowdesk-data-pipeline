{% load i18n %} {% comment %} public/partials/_region_sheet_terrain.html — the region sheet's "Highlight problem terrain" switch and its colour key (SNOW-979, SNOW-1194). Above the bulletin, under the region's name and date (Hugo, 22 Oct: mockup option A). The strip is the panels' own "Show on the map" switch, ``includes/_map_overlay_toggle.html``, inside a box of the same ``bg-tag`` that also holds the key, so the two read as one control. Since SNOW-1194 the layer paints EVERY region by its own bulletin from ``/api/problem-terrain/`` (Hugo, 22 Oct: region by region was choppy). This switch writes the same state as the layers menu's "Highlight problem terrain" row under Conditions (2026-10-23; it was the terrain filter's "By bulletin" colour until then), so it carries the row's name. The key stays this region's: one swatch per level its bulletin paints today, the undecided grey when a problem cannot be placed, then the hatch for steep ground no problem describes and the no-data hatch, which every day can show. The line under it says what the shading claims and what it does not — where the bulletin describes its problems, not a hazard map. ``static/js/map_region_sheet.js`` binds the switch to ``window.pwaBulletinTerrain`` (map.js), shows the key while it is on, and shows the zoom line while the map is too far out for the tiles. The key and the zoom line render ``hidden`` so a body painted from the cache does not flash them before the script has read the switch's state. The rows are ``includes/_bulletin_terrain_key.html``, the same key the map legend shows for the whole scale. Context (from apps.public.region_sheet.region_sheet_partial): terrain_key — ``levels`` [{level, label}] and ``undecided``. {% endcomment %}
