{% load i18n components resort_tags snowdesk_time %} {% comment %} public/partials/_place_sheet_body.html — what a tapped resort pin or saved pin's phone sheet says (SNOW-1100). Rendered by ``apps.public.place_sheet`` (``resort_sheet_partial`` and ``favourite_sheet_partial``) and swapped by ``static/js/map_place_sheet.js`` into ``#place-sheet``, an ``includes/_overlay_sheet.html`` that declares the detents peek, half and full. One fragment serves both kinds and all three detents, ordered so that each detent shows the next part of it: 1. PEEK (``data-sheet-peek``) — the header ROW, then the day: the round pin tile (``includes/_resort_tile.html``, a place's shape in search; the square danger tile is a region's), the place's name, the actions and the ×; under them, full width, "Data from " (``includes/_sheet_date_row.html``). Nothing else — no level, code or region in the header (Hugo, 21 Oct: it could not be told from the region sheet, and had too much squeezed in). A resort's action is the Save star; a saved pin's are the panel row's own "…" menu (``_favourite_row_menu_items.html``: Share → Rename → Delete). The header is ``data-sheet-drag`` and, for a saved pin, also the row the inline rename edits (``data-row-renameable``). 2. HALF (ends under ``data-sheet-half``) — a resort's curated "why it matters" line when it is written and its one-line fact summary (``resort_fact_summary``: "1,500–3,330 m · 34 lifts · 210 km piste"), then the day's weather at the place and "Full forecast →". The level is already on the peek row. 3. FULL — the region's avalanche problems, then the links onward: the day's bulletin (primary) and the resort page (secondary). With none of those there is nothing for FULL to show, so ``data-sheet-detents`` drops it. WHAT THE SHEET DOES NOT SAY (SNOW-1161, docs/decisions/the-map-opens-a- resort-in-the-sheet.md). The sheet is "this place, on the map's day"; the resort page is "this resort, today". So the full facts list, the week, the season and every blank state belong to the page: no "About this resort" list (the summary line reads the same formatter as the page's card), no "The week" (the sheet already follows the scrubber, and a week inside it read as a second date control), no sign-up prompt or curation hint where "why it matters" is unwritten, and no dashed placeholder anywhere. Context: kind — "resort" or "favourite". name — the place's name; "" for an unnamed pin. region — MicroRegion or None. day_rating — RegionDayRating for target_date, or None. level_label — the danger level's name, or "". target_date — the day the map is showing. bulletin_url — that day's bulletin page, or "". problem_cards — the bulletin's problem cards, possibly annotated. location — the place's Location, or None. weather_display — build_weather_display's result for the day's own row, or None (always None on a forward day). forward_day — on a forward day, today's forecast entry for it, or None. forecast_url — the location's forecast page, or "". resort — the Resort (a resort, or a saved resort), or None. resort_url — the resort page, or "". favourite — the Favourite (kind "favourite" only), with ``w3w_share_text`` hung on it. can_favourite, favourited, favourite_uuid, signin_url — the resort's Save star (kind "resort" only). {% endcomment %} {% trans "Unnamed pin" as unnamed_pin %} {% firstof name unnamed_pin as label %}
