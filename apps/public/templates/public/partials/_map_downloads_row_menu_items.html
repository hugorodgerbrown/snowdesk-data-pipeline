THE RULE THIS IMPLEMENTS, which supersedes the one the shared row partial and the overflow-menu partial both still described: **more than one action on a row is a "…"; exactly one action is a bare icon.** SNOW-658 ruled the other way (a visible trash on every row, one tap not two) and SNOW-830 narrowed it for the routes row alone; Hugo reversed it on 2026-09-07 for every panel. On this panel it means: a REGION on this device Sync now and Remove → this menu. a CUSTOM AREA or DROP ZONE Sync now, Rename and Remove → this menu. a row NOT on this device Download alone → the bare download icon. an ORPHAN Remove alone → the bare trash. SNOW-951 replaced the two CONDITIONAL items this menu used to carry — Repair (offered only to a row the render check had already failed) and Refresh (offered only to a row whose last run recorded a content shortfall) — with ONE UNCONDITIONAL item offered to every row that is downloaded here. Both old items were remedies for a fault, so neither was on the row at the moment a user actually wants them: the one before leaving the car park, when nothing is wrong yet and everything is about to be needed. "Sync now" runs both halves in that order (see map_basemap_downloads.js's `syncArea`), so the row offers one thing that always works rather than two that usually are not there. The consequence is that a REGION row on this device is always a menu now — Sync now and Remove are two actions, and design-system rule 5 collapses two into a "…". That is the rule applying rather than an exception to it. ORDER: Sync now → Rename → Remove. The restorative action leads, the rename follows, and the destructive item is last as it is on every list in the app. The buttons are value-less here, exactly as the inline controls were: this partial is rendered ONCE inside the row `
