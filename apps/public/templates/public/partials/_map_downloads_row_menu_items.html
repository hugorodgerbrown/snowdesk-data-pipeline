THE RULE THIS IMPLEMENTS, which supersedes the one the shared row partial and the overflow-menu partial both still described: **more than one action on a row is a "…"; exactly one action is a bare icon.** SNOW-658 ruled the other way (a visible trash on every row, one tap not two) and SNOW-830 narrowed it for the routes row alone; Hugo reversed it on 2026-09-07 for every panel. On this panel it means: a REGION on this device Remove alone → the bare trash stays. a CUSTOM AREA or DROP ZONE Rename and Remove → this menu. a row NOT on this device Download alone → the bare download icon. a row that cannot render Repair and Remove → this menu. a row whose CONTENT is behind (SNOW-932) Refresh and Remove → this menu. A REGION row reaches it too, which is the one shape change this ticket makes: a region whose bulletins fell short gains a second action and so stops being a bare trash. That is the rule above applying, not an exception to it. ORDER: Repair → Refresh → Rename → Remove. The two restorative actions sit together at the top (Repair mends a map that will not DRAW; Refresh mends bulletins that are BEHIND — nearest-neighbour first), the rename follows, and the destructive item is last as it is on every list in the app. No row ever carries all four: Repair and Refresh answer different halves and Rename is custom-areas-only.
