{% load i18n components %} {% comment %} public/partials/_map_terrain_filter_sheet.html — the terrain filter's sheet (SNOW-978, SNOW-1109). The layers menu's terrain filter row is a checkbox that turns the filter on and off; the adjust (sliders) button beside it opens this sheet, and turns the filter on first if it is off. So the sheet carries no switch of its own and no availability line: the menu row's second line says when the filter is on but cannot draw (zoom in; outside coverage). It is the standard map panel: includes/_overlay_sheet.html, inset beside the roundel column on a desktop and docked to the foot on a phone, with the UGC panels' header (the layers roundel's glyph, title, ×, context line). SNOW-1109 compacted the body so it fits a phone without scrolling past the map. Each control carries its own key, so the sheet no longer includes includes/_terrain_filter_key.html (the map legend still does): - COLOUR: two equal tiles over two real radios named terrain-filter-mode — "One tint" (value match) and "By slope" (value slope, the map's slope layer since SNOW-1073). Each tile shows its own swatch. - SLOPE ANGLE: a ramp of five toggle buttons, one per slope class (labelled 30–35 … 50+; the heading carries the degrees), [data-slope-class] 0–4. In slope mode a selected class is filled with its slope colour and an unselected one carries a strip of it along its foot; in tint mode a selected class takes the accent tint. The range is contiguous: terrain_filter_core.js's tapSlopeClass decides what a tap does. Under the ramp, the no-data hatch row. - ASPECT: an SVG rose of eight wedges, each a keyboard-operable toggle (role=button, aria-pressed, [data-octant] N=0 … NW=7 — the aspect wheel's order and msgids, includes/_aspect_wheel.html), with an "All" centre that turns every aspect on, or every one off when all are on. - ELEVATION: an SVG mountain drawn after elevation_icon's geometry (apps/public/templatetags/card_tags.py) on a 1,000–4,500 m scale, the band shaded and each set bound a dashed line, then two native selects, "Above" and "Below". Their options are written by the script, in 100 m steps, each list cut at the other's value. The visual states (wedge, ramp tile, mountain) are the .terrain-* rules in src/css/main.css: they hang off aria-pressed and the ramp's data-mode, which Tailwind's utilities cannot combine.
