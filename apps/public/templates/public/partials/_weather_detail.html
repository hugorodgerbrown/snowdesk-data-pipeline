{% load i18n static components %} {% load weather_icons %} {% comment %} public/partials/_weather_detail.html — weather-sheet body (SNOW-761). Server-rendered by ``apps.public.api.weather_detail`` and injected into the map's weather sheet by ``static/js/map_weather_detail.js`` when a condition symbol on the map is tapped. THIS IS A CARD, NOT A PAGE. It briefly carried the outlook chart, the seven-day strip and per-day hourly tables; that was too much for a surface reached by tapping a symbol, and it was the wrong place for all three. What is left answers one question — what is it doing there, now — and hands the rest to the full forecast behind a link. (None of those three components still exists: SNOW-789 rebuilt that page around a day picker.) The trim is also what the payload wanted: the hourly tables alone were 79% of this response. Content, in the order a skier reads it, split across the phone detents (SNOW-1101; docs/decisions/sheet-detents-are-phone-only.md): PEEK — the day's line: the symbol, the name, the high/low, new snow and wind, then the ×. The row is ``data-sheet-peek`` and ``data-sheet-drag``. HALF — the rest: elevation and date, the condition, the figures that change a plan (freezing level, snowfall, wind, precipitation chance), and a link to the full forecast when there is one. FULL — the day's meteogram (includes/_hourly_chart.html), when the row carries an hourly series; without one the detents narrow to peek and half, and a day with no row narrows them to peek alone. Nothing here is user-supplied: a Location's name is curated and a Weather row comes from Open-Meteo, so there is no untrusted text on this surface. Context: location — locations.Location the reading belongs to. heading — str: the location's name, or a coordinate fallback. weather — weather.Weather row for the requested date, or None. hourly_chart — HourlyChart for the row's own day, or None (apps.weather.services.hourly_chart.build_hourly_chart). display — WeatherDisplay for that row, or None (apps.weather.services.weather_display.build_weather_display). target_date — datetime.date the sheet was opened for. forecast_url — str: URL of the full forecast for this location, or "". Empty for a location with no page of its own — see the view. The link is omitted rather than pointed somewhere that is not a forecast. {% endcomment %}
