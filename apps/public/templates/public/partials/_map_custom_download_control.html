{% load i18n %} {% comment %} public/partials/_map_custom_download_control.html — offline-downloads roundel (SNOW-522; behaviour rewritten by SNOW-634 and SNOW-635). Takes the bottom-right utility-stack slot the per-region download control (_map_download_control.html) vacated when it moved back into the ribbon header. The glyph is unchanged from SNOW-522 (a viewfinder/frame, distinct from the per-region control's plain download arrow) and the roundel is still NOT hidden-until-focused — unlike the per-region control it has no dependency on a focused region, so it is always present in the bottom-right stack (matching every other roundel there). SNOW-522 through SNOW-632 had this roundel open the "Download a custom area" framing overlay (#map-frame-overlay, _map_embed.html) directly, with its own five-state machine (idle/busy/done/error/offline) painted onto it by map.js. SNOW-588 then added a SEPARATE "Manage downloads…" row in the layers menu, opening a sheet that listed every downloaded area (regions AND this custom one) — the same subject reachable two ways, one of them buried in a menu about map layers. SNOW-634 collapses them: clicking this roundel now opens the downloads sheet (public/partials/_map_downloads_sheet.html) — the layers-menu row is gone, this IS the way in — and "Download a custom area" is an action inside that sheet ([data-panel-add]) rather than the roundel's own click. The roundel is therefore reduced to two states (data-download- state: idle | done), driven by static/js/map.js's mapCustomDownloadControlInit's `_renderControl`: "done" means the DEVICE holds at least one downloaded area (region or custom, excluding an orphaned/incomplete bucket), not that this one custom area is fully cached — a user with five downloaded regions and no custom area now reads `done`, correctly, rather than the old per-area probe's `idle`. Clicking is unconditional — no busy state to guard (framing hides #map-controls-br, this roundel's own container, for as long as it is open, so it can never be clicked mid-run) and no offline guard (the sheet lists and deletes offline, which is exactly when storage pressure is felt). aria-controls points at the sheet it now opens, not the overlay. SNOW-635: dropped the `data-area-label` attribute this element used to carry ("Custom area", the display name a completed download recorded onto its own `basemap.customArea.name` at download time). Every custom area now gets its own sequential default label ("Custom area N", derived from `ordinal` at render time — see _map_downloads_sheet.html's `default-custom-name` string) rather than a single frozen-at-download-time one, so this element no longer has a name to hand it. Takes no context. {% endcomment %}
