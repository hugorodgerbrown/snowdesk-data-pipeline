{% load i18n %} {% comment %} public/partials/_map_custom_download_control.html — "Download a custom area" control (SNOW-522). Takes the bottom-right utility-stack slot the per-region download control (_map_download_control.html) vacated when it moved back into the ribbon header. Clicking this roundel opens the framing overlay in _map_embed.html (#map-frame-overlay) — a Google-Maps-style dim mask with a fixed centred frame the user pans/zooms the map under, with a live "up to N MB" readout — rather than downloading immediately like its per-region sibling: there is no fixed area to size until the user has framed one. Same roundel/state-machine markup idiom as _map_download_control.html (data-download-state, per-state SVG glyphs, --download-progress fill) and the same .map-download-control CSS class for the shared glass-circle chrome (static/css/map.css) — but a distinct glyph (a viewfinder/frame, not a plain download arrow) so the two controls read as different affordances at a glance, and it is NOT hidden-until-focused: unlike the per-region control it has no dependency on a focused region, so it is always present in the bottom-right stack (matching every other roundel there). States (data-download-state): idle | busy | done | error | offline — no "no-region" (there is always a map area to frame) and no persistent "disabled" (the over_ceiling backstop applies to the CURRENT framed area, shown live in the overlay's CTA bar instead, not to this roundel). "error" (SNOW-568) means the last run failed and the area is NOT available offline; unlike the region control's inert states it is clickable, and the framing overlay is left open behind it so the framed area survives for a retry. static/js/map.js's mapCustomDownloadControlInit drives the state and rewrites the title/aria-label to match — exactly like its per-region sibling, "done" is probed from real pinned-cache contents (every per-area bucket, unioned — SNOW-586) against the persisted saved-area's centre tile, never a stored flag. data-area-label (SNOW-586): the translated display name recorded onto the custom area's meta:app row (`basemap.customArea.name`) and shown in the whole-area-eviction confirm banner naming areas that would be removed to make room for a new download. A JS-assembled string would be permanently English (no JS i18n catalogue in this project — see docs/decisions/per-area-pinned-basemap-caches.md); this is a template attribute precisely so {% trans %} can reach it.
