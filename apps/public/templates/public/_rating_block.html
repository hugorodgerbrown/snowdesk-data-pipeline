{% comment %} apps/public/templates/public/_rating_block.html — Single problem card for the bulletin page layout. Expects the following variables in scope: card — one entry from panel.problem_cards (produced by build_problem_cards or _problem_cards_from_render_model_traits for ALBINA bulletins). Keys: problem_type, category, danger_level, label, time_period_label, aspects, elevation, core_zone_text, comment_html, panel_title (the provider's own words for the trait, e.g. "Dry avalanches, whole day" / "Gliding avalanches". The render model fills a fallback for every trait (render_model.py's _TITLE_FALLBACK), so in practice this is always populated — all 9,614 traits in production carry one. The template still guards it because the title bar now carries the level colour, and a blank row would lose it), show_time_pill (bool — True only when the bulletin splits the day, i.e. some trait is earlier/later. Set in views.py from is_time_variable so the partial needs nothing from the panel context), subdivision (optional — per-period suffix display char, e.g. "-", "=", "+"; empty when not available. No longer rendered here — SNOW-727 moved it to the Day Risk Profile row as words), avalanche_type (optional — "slab", "loose", or None), avalanche_size (optional int 1-5; ALBINA-only), avalanche_size_label (optional translated Promise; ALBINA-only — the EAWS word for the size, e.g. "Large"), frequency_label (optional translated Promise; ALBINA-only, None when raw frequency was missing or "none"), stability_label (optional translated Promise; ALBINA-only), danger_patterns (list of {"label": "GM.1", "title": "..."}; ALBINA-only; empty list for SLF/MeteoFrance) Renders: 0. Title bar — always. Carries the provider's words for the trait and, via data-level, the saturated EAWS colour for the danger level (SNOW-727). Levels 1–3 take --color-eaws-{level} with -fg copy; 4 and 5 borrow the other dark value each level already owns, because the EAWS red the two of them share takes no companion copy colour that clears WCAG AA. Rules and the measured ratios live in src/css/main.css, beside the .danger-band blocks. 1. Hazard bar — the pale half of the pair: EAWS tint behind the hazard pictogram (encodes kind + level) and the problem name. Carries the avalanche-type chip, and a time chip only on a bulletin that splits the day. The dry/wet category pill and the level-number chip were removed in SNOW-727 — the title bar and the pictogram already carried both. 2. Aspect / elevation row — three-way conditional on card.prose_mentions_spatial: (a) structured data present (card.aspects or card.elevation) → the aspect rose and elevation chip render verbatim (data-testid="aspect-elevation-row"). (b) prose-only and card.prose_mentions_spatial=True → a row reading "See description below" (data-testid="aspect-elevation-fallback"). (c) prose-only and card.prose_mentions_spatial=False → a row reading "All aspects · all elevations" (data-testid="aspect-elevation-allscope"). 3. EAWS matrix row — only when any of size / frequency / stability is present (ALBINA-only). One chip per axis. Skipped entirely for SLF and MeteoFrance cards, whose source data carries none of these. 4. Danger pattern tags — small GM.N chips with full-name tooltips, sourced from customData.LWD_Tyrol.dangerPatterns (ALBINA-only). Absent for SLF and MeteoFrance cards. 5. Prose — the problem's comment field rendered in full, no truncation. 6. Field notes — Snowdesk's own note for this problem type, below a rule and credited to the SLF interpretation guide (SNOW-673). A collapsible panel, closed by default.
