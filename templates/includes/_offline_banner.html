Revealed by static/js/pwa_offline.js when: * ``navigator.onLine === false``, or * a fetch / HTMX request just failed with a network error, or * the service worker has latched into offline mode (SNOW-742 — see below; this one can be true while ``navigator.onLine`` is still true). The summary row reads "Offline — last synced ", where ``static/js/pwa_offline.js`` fills the ``data-role="synced-at"`` span with a relative phrase ("6 minutes ago") derived from ``sync.last_at`` — the wall-clock time this device last reached the server, persisted to IndexedDB ``meta:app``. The phrase re-renders on a timer while the banner is shown, so an open banner keeps counting up rather than freezing. It falls back to an em dash until the first sync is known. Opening the caret reveals a short explanation of the offline state. There is one clock, not two: a ``freshness.last_generated_at`` companion read from ``X-Data-Generated-At`` (SNOW-370) was absorbed and persisted but never surfaced anywhere, and SNOW-615 removed it. SNOW-742 — two states, not one. The banner now distinguishes "the network is failing" from "the app has given up on the network", because they make different promises to the user and only one of them is true at a time: * struggling (``offline-message`` / ``offline-explainer``) — requests are still being attempted, and the app will update as soon as one lands. * latched (``latched-message`` / ``latched-explainer``) — the service worker has stopped calling the network entirely after three consecutive read timeouts, and is serving downloaded data only. This state can be reached while ``navigator.onLine`` is still TRUE (a radio that is attached but has no route — the Underground), which is exactly why the banner cannot key off ``onLine`` alone. Both variants of the message and the explanation are rendered here and toggled by ``hidden`` in static/js/pwa_offline.js, rather than having their text set from JavaScript: ``makemessages`` never scans ``static/js``, so a string built there ships as English to every locale. ``bin/i18n-lint`` enforces this. See docs/i18n.md. The two buttons are mutually exclusive, each offered only where it does something — "Try reconnecting" while latched, "Stay offline" while merely struggling (a user who can see the banner and knows they are about to lose signal for the day). Spec §3.5, §10.1, §12.6 — freshness is non-negotiable, and an app that has stopped asking the server has to say so. In-flow, not ``fixed`` — it sits as the first child of the body, above ``includes/nav.html``, so when revealed it pushes the nav and page content down rather than overlapping the nav bar. ``hidden`` collapses it to zero height.
