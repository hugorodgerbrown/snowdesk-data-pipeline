{% load i18n components %} {% comment %} templates/includes/_sheet_header.html — Shared header for map fly-out sheets. Renders a title plus a persistent × close control. Used by any sheet state that lacks its own close affordance (favourites, report, and downloads map sheets). The × dispatches through ``data-action`` — it does not call JS directly. SNOW-486: ``close_action`` is conventionally ``"dismiss"`` — the owning sheet is a ``[data-overlay]`` element (includes/_overlay_sheet.html), so static/js/overlays.js's shared delegated handler picks up a ``[data-action="dismiss"]`` click without the sheet's own JS needing to bind a listener for it. Parameters (passed via ``{% include … with … %}``): title (string) — Heading text rendered next to the ×. close_action (string) — Value for the button's ``data-action`` attribute. Pass "dismiss" unless the owning sheet has its own bespoke close handler. title_class (string, optional) — Font-size/weight utilities for the title. Defaults to the original ``text-sm font-semibold``; the "Manage downloads" sheet (SNOW-645 review) passes ``text-lg font-bold`` for its own larger heading. ``text-text-1`` is always applied underneath whatever this carries, so callers only need to state size/weight. icon_template (string, optional) — Template path for a glyph rendered in a 26×26 box before the title (SNOW-658). The three UGC panels pass the glyph of the ROUNDEL that opens them (includes/_icon_downloads.html, _icon_favourite.html, _icon_observation.html) at 22px: Hugo's design makes it the panel's only identity mark, confirming which roundel was tapped. A template path rather than a name, matching the ``rows_template`` mechanism includes/_ugc_panel.html already uses — Django has no slot mechanism, and a name would need a lookup table this partial has no business owning. Sheets with no roundel of their own (the favourite create form, the report form) pass nothing and render exactly as before. SNOW-645 review, three times over on the × itself: 1. It used to be ``text-lg leading-none px-1`` — a ~26×20px hit target, well under the 44×44 minimum. First pass: centred the SAME small glyph inside a new ``h-11 w-11`` (44×44px) box, growing the tap target only. Wrong call — Hugo's report: "the 'x' is very small — it needs to fill the 44x44". Reversed: the mark itself now scales to read at the control's own size, not a small glyph floating in a big invisible box. 2. The mark is no longer the literal "×" (U+00D7 multiplication sign) character. It does not scale well — past a certain size it reads as a thin, off-centre mathematical symbol whose optical centre sits high in the line box, rather than a close icon. Replaced with the SAME stroke-based inline SVG cross idiom ``#map-help-close`` / ``#home-intro-close`` already use in ``_map_embed.html`` (``viewBox="0 0 24 24"``, ``stroke="currentColor"``, round caps/joins) — ``currentColor`` means it inherits ``text-text-2``/``hover:text-text-1`` exactly as the old glyph did, no separate colour to keep in sync. 3. Reconciled against the Claude Design source: the glyph is 20×20 (was 22×22 — a 2px difference, tightened to match exactly rather than left as a rounding gap), and the 44×44 hit box now carries a ``-mt-3 -mr-3`` negative margin (``-12px`` top/right, matching the design) so the OVERSIZED tap target does not inflate the header row's own rendered height the way a plain ``h-11 w-11`` box would — the row's height is still set by its shortest content (the title line), not by the invisible-but-laid-out corners of an enlarged button. The hover fill (``hover:bg-chip-strong``, ``rounded-tag``) is new too — the design gives both this control and the overflow trigger the same translucent hover backdrop, which the plain colour-only ``hover:text-text-1`` this button already had did not provide. One size for all three consumers, deliberately — not a second ``title_class``-style parameter: checked against favourites (``_favourites_surface.html``) and report (``observations/_report_form.html``, both tighter headers than downloads) and one glyph size in a 44×44 box reads sensibly in all three rather than needing a per-sheet override. SNOW-658 trims that glyph from 20×20 to 18×18 and moves its class string onto the ``icon_button_classes`` tag (apps/public/templatetags/components.py). Hugo's map-panel design draws every icon control in a panel the same way — this ×, a row's Rename, a row's Remove — at a 44×44 target with a 17–18px glyph, and those controls now live in five templates across three apps. The 2px is not the point; one decision in one place is. The fix, when tests are back in scope, is a structural locator (e.g. scoped to this header's own row, or an ``aria-label="Close"`` filter) rather than one keyed to the glyph's text. {% endcomment %}
