{% comment %} templates/includes/_switch.html — Reusable ON/OFF switch (SNOW-645). Built for the "Manage downloads" sheet's map-overlay control ("Show areas on the map") — the first place this app needed an iOS-style switch rather than a checkbox. There was no such primitive before this (checked against apps/public/design_tokens.py and the component library), so it is built here as a real, reusable partial rather than inline in that one sheet — "reuse first, extract second, inline never". It is a real under the hood, drawn as a track + thumb using Tailwind's `peer` variant — CSS alone, no JS. That is load-bearing, not a style choice: a
with a click handler would need its own keyboard handling (Space/Enter), its own focus ring, and its own aria-checked bookkeeping to match what a real checkbox gives for free. `role="switch"` remaps the ANNOUNCED role from "checkbox" to "switch" (WAI-ARIA's switch pattern: a plain checkbox input with this one attribute) while every native behaviour — Tab focuses it, Space/Enter toggles it, ``:checked`` drives its state — is untouched. The input itself is visually hidden (`sr-only`, not `hidden` or `display:none` — it stays in the accessibility tree and keyboard-focusable) in favour of the track+thumb pair drawn next to it, which read its `:checked` state via the `peer` / `peer-checked` / `peer-focus-visible` Tailwind variants. This partial renders ONLY the control — no visible text label — because a caller almost always wants that label positioned and styled as part of its own row (see _map_downloads_sheet.html's overlay-toggle panel), not fixed by this partial's own markup.
