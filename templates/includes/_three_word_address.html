{% load i18n %} {% comment %} includes/_three_word_address.html — a location as a three word address. Extracted from trips/partials/_trip_meeting_address.html (SNOW-882), which was where this markup lived while a trip's meeting point was the only place that had an address. It now serves any location that has one, so it takes a LOCATION rather than a trip. THERE IS ALWAYS A FALLBACK. Flag off, no key, the upstream down, the address not resolved yet — there is never a blank where the place was. Which fallback depends on the caller: - With ``place`` (a trip's meeting point, SNOW-1214), the sentence placing the point against its route — "On the route, 9 km in" — and an "Open in maps" link carrying the coordinate. A meeting point NEVER shows its latitude and longitude, not even in a title: the group needs to know where to stand, and the link is how they navigate there. - Without it (a favourite), the coordinate pair, which moves to the element's title when the address IS shown, so the paste-into-a-map-app affordance survives at no visual cost. THE ADDRESS IS A LINK to what3words' own map, which is the only place the 3m square can be SEEN. Three words are not self-evidently a place: somebody working out whether they can find the spot needs the square on a map, and sending them to search for the words themselves would be asking them to do the lookup by hand. Off-site, so ``target="_blank"`` and ``rel="noopener noreferrer"`` — the destination is a third party's page and must get no handle on this one. A three word address is NOT A NAME ANYBODY CHOSE. It is a deterministic encoding of the same 3m square, so ///filled.count.soap and 46.080012, 7.318197 say exactly the same thing and neither invents anything. That is what makes this safe on a location minted for one trip or one dropped pin, which carries no name deliberately — naming a place is a curation act (see apps/trips/services/trips.py). THREE CALLERS at three sizes: the trip list card's footer strip (12px), the trip view's details grid (15px), and the favourite card's locate link, which is why the size is a parameter rather than baked in. Context: location : Location — read for the coordinate fallback. words : str|None — the address WITHOUT its /// prefix, which is presentation and is added here. url : str|None — where that address links to. None exactly when ``words`` is, so the coordinate fallback can never grow a link to nowhere. size_class : str, optional — the type utility for both states. Default ``"text-xs"``, the list card's size. place : str, optional — SNOW-1214. The sentence placing the location against a route, from ``apps.trips.services.meeting_place.sentence``. When set, no coordinate is ever rendered, title included. maps_url : str, optional — with ``place``, the "Open in maps" link (``meeting_place.maps_url``). data_testid : str, optional — set on the rendered element. {% endcomment %} {% with lat=location.latitude|floatformat:6 lon=location.longitude|floatformat:6 %} {% if words and url %} ///{{ words }} {% elif place %} {{ place }} {% if maps_url %} · {% trans "Open in maps" %} {% endif %} {% else %} {{ lat }}, {{ lon }} {% endif %} {% endwith %}
