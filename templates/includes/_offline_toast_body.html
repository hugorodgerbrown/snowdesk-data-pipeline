{% load i18n %} {% comment %} templates/includes/_offline_toast_body.html — the body slot of the connection-status toast (SNOW-748). Rendered into ``includes/_toast.html``'s ``data-toast-body`` span via that partial's ``body_template`` parameter; see ``includes/_offline_toast.html`` for the caller and the reasoning behind the surface as a whole. This file carries what ``includes/_offline_banner.html`` carried before SNOW-748 removed it: * the summary line — " — last synced ", where ``static/js/pwa_offline.js`` fills the ``data-role="synced-at"`` span with a relative phrase ("6 minutes ago") derived from ``sync.last_at``, the wall-clock time this device last reached the server, persisted to IndexedDB ``meta:app``. It falls back to an em dash until the first sync is known, and re-renders on a 30s timer while the toast is OPEN so the phrase counts up rather than freezing at the value it had when the user pressed the symbol. * the rubric — one explanation per state, all rendered here and toggled by ``hidden``. Four states, not three. The banner only ever appeared when something was wrong, so it had nothing to say about a working connection; the header symbol this toast hangs off is permanent and clickable at any moment, so "everything is fine, and here is when you last synced" is now an answer the user can ask for. The other three are carried over unchanged: * online (``online-message`` / ``online-explainer``) — the app is using the network normally. * struggling (``offline-message`` / ``offline-explainer``) — requests are still being attempted, and the app will update as soon as one lands. * latched (``latched-message`` / ``latched-explainer``) — the service worker has stopped calling the network entirely after three consecutive read timeouts, and is serving downloaded data only. This state can be reached while ``navigator.onLine`` is still TRUE (a radio that is attached but has no route — the Underground), which is why nothing here keys off ``onLine`` alone. * forced (``latched-message`` / ``forced-explainer``) — the same behaviour, asked for by the user from the "Offline mode" switch in the account menu (``includes/nav.html``). It shares the summary line, because the summary answers "is this app contacting the server" and the answer is the same; it does NOT share the explanation, because the latched one asserts there is no usable connection and here there may well be one. Nothing probes this state, so nothing will end it but the user. Every variant is rendered server-side and toggled by ``hidden`` in static/js/pwa_offline.js rather than having its text set from JavaScript: ``makemessages`` never scans ``static/js``, so a string built there ships as English to every locale. ``bin/i18n-lint`` enforces this. See docs/i18n.md.
