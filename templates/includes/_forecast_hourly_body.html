{% comment %} templates/includes/_forecast_hourly_body.html — one day's hourly detail. Rendered inside ``_collapsible_panel.html``'s body wrapper by ``_forecast_panel.html``, once per day that carries an hourly series. Reads ``hourly`` and ``testid_prefix`` from the inherited context; ``hourly`` is a list of ``apps.weather.types.HourlyRow`` dicts — either the ``Weather.hourly`` column (the row's own day) or a forward day's nested ``hourly`` key. Every column renders an em-dash when its key is null, so a row short of one variable keeps the others aligned. Open-Meteo drops variables depending on which model backs the coordinates, so a null is ordinary rather than exceptional. Snowfall is the exception: it stays blank on zero, because a column of "0.0 cm" down a dry week is noise. Wind direction shares the wind cell rather than taking a column of its own — a bearing means nothing beside a speed it does not modify. The arrow points AT THE SOURCE and the accessible label names that same source, which is the aspect being loaded; SNOW-785 made the two agree, and the glyph used to fly downwind. See ``apps.public.templatetags.weather_tags``. Rows written before SNOW-778 have no direction key at all, so the arrow is presence-checked and the speed renders alone when it is absent. {% endcomment %} {% load i18n weather_tags %}
