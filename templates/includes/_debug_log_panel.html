{% comment %} templates/includes/_debug_log_panel.html — on-device debug trace panel (SNOW-812). Rendered from public/base.html ONLY when the ``debug_log`` waffle flag is active — i.e. for members of the GRP_DEBUG group. For everyone else neither this markup nor static/js/debug_log.js reaches the page at all, so the instrumented call sites across map.js, sw.js and friends stay optional-chain no-ops against an undefined ``window.pwaDebugLog``. The flag decides who gets the toggle. Recording itself is a per-device choice made here and persisted (localStorage + a ``debug.enabled`` meta:app row + a postMessage to the service worker), so holding the flag costs nothing until somebody switches the trace on. Why an on-page panel rather than the console: the failures worth chasing here happen on a phone, offline, often mid-download — with no devtools attached and no way to attach any. Copy puts the whole trace on the clipboard so it can be pasted into a Linear comment from the device that produced it. {% endcomment %} {% load i18n static %}
