{% load i18n %} {% comment %} templates/includes/_pwa_update_modal.html — Non-dismissable PWA update modal. Rendered hidden by base.html on every public page. Revealed by static/js/pwa_version_check.js when ``/api/version`` answers ``update_required: true`` — the server has listed this build in ``settings.APP_BLOCKED_VERSIONS`` (spec §3.4 forced-update, SNOW-609). The modal stays open until the user clicks "Reload now"; nothing is cleared and nothing reloads before that click. The body copy says what is wrong and what to do, and nothing about local state (SNOW-869). It used to say the reload "refreshes the offline copy of the app" and then reassure that downloaded maps and saved data were kept — the reassurance was load-bearing only because the clause before it raised the alarm: "clears" on a mostly-offline app reads as "deletes my 500 MB of downloaded maps". Removing the alarm removes the need for the answer, and the whole pair goes. The rule, shared with includes/_sw_update_banner.html: warn before deleting something, say nothing otherwise. The click clears ``snowdesk-shell-*`` / ``map-shell-*`` only — that is code, not the user's data, and SNOW-609 deliberately kept it that way for this path (see ``pwa_version_check.js``'s ``clearShellAndReload``). Nothing the user owns is at risk, so there is nothing to disclose. SNOW-486: markup delegated to the shared modal primitive (includes/_overlay_modal.html) — this file now only supplies the copy/ids. See that partial's header comment for the design contract (full-screen backdrop, centred card, no dismiss).
