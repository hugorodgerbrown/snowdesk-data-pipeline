Revealed ONLY when the service worker is stuck on a stale shell (SNOW-1025): the server has moved on (``static/js/pwa_version_check.js`` confirmed an ``X-App-Version`` drift), the controlling worker holds a different shell from the one the server would serve (SNOW-952), and the browser cannot install a replacement on its own. The gates live in ``static/js/sw_register.js`` (``revealUpdateBannerIfStuck``). A routine update never shows this banner: a waiting worker is applied silently the next time the page is hidden. The copy is plain. SNOW-869 named the two builds ("Update available (3de6af2) / You are on 5f20005"); SNOW-1025 removed that. A person who is stuck needs to know what to press, not which commit they are on. Clicking Reload triggers ``SKIP_WAITING`` on the waiting worker when one exists, otherwise clears the SW shell cache and reloads — see ``sw_register.js``. Clicking × dismisses for the rest of this page's lifetime. The body copy does NOT say what the reload keeps. SNOW-609 added "your downloaded maps and saved data are kept" so a user weighing "will this cost me my downloads?" did not have to guess; SNOW-869 removed it, because a reassurance is a warning in disguise. Naming the thing that survives plants the idea that it might not — and both reload paths touch only the ``snowdesk-shell-*`` / ``map-shell-*`` caches, so nothing the user owns is at risk and there is nothing to disclose. The rule that replaces it: warn when we are about to delete something, say nothing when we are not. ``pwa_reset.js``'s everything-goes wipe is where a warning belongs, and it has one.
