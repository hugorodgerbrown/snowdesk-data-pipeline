{% load i18n static weather_tags %} {% comment %} templates/includes/_forecast_panel.html — multi-day outlook for one location. Two parts: 1. A compact day strip — one column per day: weekday label, condition icon, hi/lo temperature, that day's freezing level, its wind, and a snowfall chip when the day's ``snowfall_sum`` is non-zero. The column is ``w-24`` rather than ``w-20`` so the wind value keeps its unit — a bare number sitting under "2400 m" says nothing about which is which. Gusts are deliberately absent: ``_weather_panel.html`` has a wrapping row to spend on them and this column does not (SNOW-780). 2. Expandable hourly detail — one ``_collapsible_panel.html`` per day that carries an hourly series, listing it via ``_forecast_hourly_body.html``. SNOW-761: the days come from ONE ``Weather`` row — its own ``observed_on`` leads, and the rest are the entries in its ``forecast`` column (``build_point_forecast_panel``). Before the rebuild they were N sibling rows from a second table. **``hourly`` is present on only the first few forward days**, so part 2 tests each day for one rather than assuming; a day past that horizon simply contributes no panel. Consumer: the location forecast page (``/weather//``), and nothing else. SNOW-783 took this strip off the resort page and the favourite card — both drew the same week the forecast page already owned, the resort page once per curated altitude — so each of those now shows the day and links here. Context: panel : ForecastPanel — ``{"days": [ForecastPanelDay, ...]}`` from ``apps.weather.services.weather_display.build_point_forecast_panel``. testid_prefix : str — prefix for every ``data-testid`` in this partial and its included children. Defaults to ``forecast``. {% endcomment %}
