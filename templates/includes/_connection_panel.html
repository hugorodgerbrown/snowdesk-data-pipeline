SNOW-1415: one answer per area ------------------------------ The panel exists to give a reader confidence that the map will work offline inside the areas they chose (docs/decisions/the-connection-panel- answers-per-area.md). Before this ticket it only made sense to someone who knew how the app works inside: a "last synced" clock, a "Downloads updated" age, an Offline mode switch, "Get ready for offline", a job counter, a "Download for offline" link that opened a diagnostics page, and a Debug log. Now it holds: * the state line — "Online", "Offline" or "Offline mode" — with an explanation only for the two offline states, where something is not as usual; * ONE ROW PER DOWNLOADED AREA, each answering "will this work offline?" with the verdict /offline/'s panels give (``offline_journey_core.js``: ``stagesFromRecord`` + ``verdictFor``), over the stored record alone: - ``ready`` — yes; - ``refresh`` — mostly, with its first reason (the bulletins and weather, or the reader's things); - ``open-map`` — the map is missing, with the way to download it again; - ``unknown`` — no page that can read tiles has checked it yet; - ``running`` — the Sync below is on this area now; * ONE Sync button, which drains the queue and then syncs every area (``offline_ready_core.js``). On the map it runs here; everywhere else it navigates to ``/map/?sync=all`` (the block's ``data-map-url``), and the map runs it on arrival with this panel open; * the way back to the network, in the two offline modes only. The Offline mode switch and the Debug log moved to /offline/, which is now the debug page, linked from Help and settings rather than from here. A row is not interactive yet: a tap is reserved for the inventory (SNOW-1418). Still an ANCHORED POPOVER, not a toast, and still NOT ``role="menu"``: a disclosure holding a small form. Four network states, carried over from SNOW-748: * online — the app is using the network. No explanation: the rows are the content. * struggling (``offline-message`` / ``offline-explainer``) — requests are still being attempted. * latched (``latched-message`` / ``latched-explainer``) — the service worker has stopped calling the network after three read timeouts. * forced (``latched-message`` / ``forced-explainer``) — the same, asked for by the user from the Offline mode switch on /offline/. The online state is what renders before any script runs, which is the right default: both offline modes are service-worker decisions.
