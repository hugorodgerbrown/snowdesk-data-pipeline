The iOS startup images (includes/_pwa_splash.html) cover from tap to first paint; this covers from first paint to the app being worth looking at — on the map page that is the gap while MapLibre fetches its style and first tiles, during which the page has painted chrome over an empty #map. It is drawn to MATCH the OS launch screen exactly. Done right the user never sees a handover at all — one splash that happens to change owner halfway through. The OS draws a different launch screen per platform, so there are two marks and the inline gate picks one (SNOW-1112): * Android (and anything that is not iOS): Chrome generates the splash from the manifest — background_color, and the MASKABLE icon cropped to a circle. So the default mark is that same file, clipped to the same circle at the same size: the whole icon as a 240px circle, measured off a Pixel 9 on Android 17 (see docs/pwa-launch.md). * iOS: the launch screen is a startup image built around the rounded tile (bin/build-pwa-splash), so the tile is shown instead, at the proportion of the shorter edge that script uses. Every value here — the background, both images — comes from PWAEnvironmentIdentity via the site_environment context processor, the same object serve_manifest reads, so a staging install can never paint the production logo (the SNOW-1112 bug: the src was a hardcoded production path). tests/public/test_pwa_launch_parity.py holds it.
