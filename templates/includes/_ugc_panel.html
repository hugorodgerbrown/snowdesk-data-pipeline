{% load i18n components %} {% comment %} templates/includes/_ugc_panel.html — the shared skeleton for the three map panels that manage a user's own data (SNOW-658). Downloads, favourites and field observations all answer the same question — "what have I got here, and how do I add to it or get rid of one?" — and all three sit on the same map behind the same kind of roundel. Until this partial they shared exactly one element (the "Show X on the map" switch) and diverged at every other point of contact: three sheet-scroll models, two title sizes, three body wrappers, three row shapes. Hugo, opening all three side by side: "they serve the same function… and yet they are all different." The "Manage downloads" sheet is the reference — it came from Hugo's own mock (see the SNOW-645/SNOW-635 notes in public/partials/_map_downloads_sheet.html), so its skeleton is what got extracted here and the other two conform to it, not the reverse. SNOW-658 (Hugo's "Map panels — common format" design): the shell is five parts, always in this order, and what varies between the three panels is only ever their contents. 1. HEADER — includes/_sheet_header.html, carrying the icon of the ROUNDEL that opens this panel and the sentence-case title at ONE size for all three (`text-lg font-semibold`). Both are fixed here rather than exposed as style parameters: a per-caller title size is precisely the drift this partial exists to end, and the icon is the panel's only identity mark — the thing that confirms which roundel was tapped. 2. CONTEXT STRIP — one 13px muted line saying where this panel's data lives ("…stay on this device", "…are private and not shared", "…are shared with the community"). Downloads alone extends it, via `header_template`, with its budget meter below that line. 3. LIST — a mono uppercase section label on a rule, then the rows, which are separated by hairlines and are NOT cards: no boxes inside the panel. The scroll region is the only part that scrolls, so the header above and the CTA/switch below stay pinned. 4. ADD CTA — one full-width outlined button, exactly one per panel. 5. MAP TOGGLE — includes/_map_overlay_toggle.html at the foot, so the map BEHIND the sheet is the last thing read rather than the first. The outer flex column runs at the 18px (`gap-4.5`) rhythm and carries `min-h-0 flex-1` so it fills — and is allowed to SHRINK inside — the bounded box includes/_overlay_sheet.html's `scroll_body=True` renders. `min-h-0` is load-bearing: a flex child defaults to `min-height: auto` ("never shrink below my content"), and without the override the list refuses to scroll and pushes the CTA and the switch off-screen instead. Composition. Django has no slot mechanism, and the three shapes we need to vary (a rows region, an optional header extra) are markup, not strings. Of the three ways to do this — a caller-side wrapper that duplicates the chrome, a custom templatetag, or a template PATH passed in and `{% include %}`d — only the third leaves no class string duplicated across the three call sites and adds no new mechanism to the codebase: includes/_collapsible_panel.html's `body_template` already does exactly this, for exactly this reason. So each caller owns a small rows template and passes its path. The CTA's hook is `data-panel-add`, one name for all three panels, replacing `data-downloads-add` / `data-favourites-add` / `data-report-add`. Three names for one control is the same divergence this partial exists to remove, in attribute form. Each owning module binds its listener on its OWN sheet element (map_downloads_manager.js, favourites.js, report.js all delegate on the sheet, because the body is re-cloned on every open), so one shared hook is unambiguous — there is never more than one panel body in a given sheet. Parameters (passed via {% include … with … %}): title (string) — the sheet header's title. Required. icon_template (string) — template path for the header glyph: the icon of the roundel that opens this panel (includes/_icon_downloads.html, _icon_favourite.html, _icon_observation.html). Required — a panel with no identity mark is a state the design set out to fix. context_line (string) — the context strip: where this panel's data lives, in one translated sentence. Required, for the same reason. section_label (string, optional) — the list's mono uppercase heading ("Places", "Reports"). Optional only because downloads has TWO groups (Regions, Custom areas) and renders both headings itself, in the same style, inside its own rows template. rows_template (string) — template path rendered inside the scroll region. Owns the panel's list and, for a panel whose rows load over HTMX, the container they land in. Required. header_template (string, optional) — template path rendered inside the title block, under the context strip, so the pair reads as one unit at its own tighter rhythm rather than at the outer `gap-4.5`. Downloads' budget meter is the only user: it is the one legitimate per-panel extra, since neither of the other two costs the device anything to hold. cta_label (string) — the add-CTA's visible, translated label. Required. toggle_id (string, optional) — DOM id for the overlay switch. Omit it and the switch is not rendered at all. Required for the first three panels and NOT optional as a style choice: a panel that owns a map overlay must carry its switch, because that is where SNOW-658 moved it from the layers menu. It is optional because SNOW-686's routes panel exists BEFORE the layer it will eventually control — SNOW-687 adds the MapLibre line and the overlay bridge — and the two honest options for the gap were a switch wired to nothing or no switch. A control that silently does nothing when tapped is a worse lie than an absent one, so routes omits it and SNOW-687 passes a ``toggle_id`` when there is something for it to drive. This is the narrow inverse of the note in static/js/favourites.js about the anonymous branch KEEPING its switch: there, the overlay exists and merely has nothing in it yet, so hiding the control would hide a working view setting. Here the overlay does not exist. The overlay switch's LABEL is not a parameter. It is "Display on the map" on all three panels — the design's own wording, replacing "Show areas on the map" / "Show favourites on the map" / "Show community reports on the map". Three sentences for one control is the same divergence the shared `data-panel-add` hook removed in attribute form, so the string is fixed here, where no caller can restate it. The CTA carries `disabled:` utilities unconditionally. Only downloads ever sets `disabled` on it today (SNOW-637: starting a download needs a connection), but the styling of a disabled control is chrome, and chrome is this partial's job — a panel that later grows a disabled state should not have to remember to bring its own. {% endcomment %}
