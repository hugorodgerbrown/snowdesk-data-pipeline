{% load i18n %} {% comment %} Fixed-position notification toast partial. Required context: kind — "info" | "success" | "warning" | "error" body — Body text (single line). Rendered via {{ }}, auto-escaped. Optional context: id — DOM id on the outer element. Required when JS toggles visibility (SW banner, HTMX error banner). body_template — Template path rendered INSIDE the body slot instead of the plain ``body`` string. For a caller whose body is richer than one escaped line: SNOW-748's offline-status toast carries a summary line with a live relative timestamp plus four mutually-exclusive explanations, each server-rendered and toggled by ``hidden`` (a string set from JavaScript would ship English to every locale — ``makemessages`` never scans ``static/js``; see docs/i18n.md). Supplying it also switches the toast from its pill shape to a PANEL: ``rounded-card``, wrapped so the CTA and "×" sit under the body rather than beside it, and height-bounded with ``max-h-[60dvh]`` + ``overflow-y-auto`` — the house rule for anything fixed over the map, and ``dvh``/``dvw`` rather than ``vh``/``vw`` because the viewport units ignore mobile browser chrome (and ``vw`` counts the scrollbar). It is also WIDTH-set (``w-[calc(100dvw-2rem)]`` under the existing ``max-w-md``): a ``fixed`` flex box with no width shrinks to fit its content, which for a wrapped paragraph collapses to a ~200px column. ``flex`` IS baked in for this variant (unlike the pill — see "Display notes"), which is safe because ``hidden`` is emitted last in Tailwind's display group and so wins while both classes are present; a caller reveals by removing ``hidden`` alone. cta_label_template — Template path rendered inside the CTA button instead of the plain ``cta_label`` string. Same reason as ``body_template``: the offline toast's one button has two labels ("Try reconnecting" when the app gave up, "Use the network again" when the user chose it), both rendered server-side and toggled by ``hidden``. Emits the CTA when paired with ``cta_href``, exactly as ``cta_label`` does. cta_label — Label for inline CTA button (paired with cta_href). cta_href — Sentinel value (e.g. "#") gating CTA emission. Not used for navigation — the rendered button carries data-action="reload" so JS can wire its own handler. dismissible — Bool; default True. When true emits a "×" button with data-action="dismiss". static — Bool; default False. When True the toast renders inline (no ``hidden``, no positioning utilities; uses ``inline-flex``). Used only by the component library so variants don't pile up at the viewport bottom. timeout — Int; opt-in auto-dismiss delay in milliseconds. When supplied, renders ``data-toast-timeout`` and the shared toast controller (static/js/overlays.js) hides the toast that many ms after it becomes visible. Omit for a toast a caller dismisses itself (e.g. bulletin.html's share toast already runs its own timer — do not also pass ``timeout`` there, or the two would race harmlessly but redundantly). SNOW-486: the outer element carries ``data-overlay data-overlay-hide= "class"`` (except when ``static``) so a "×" click is caught by static/js/overlays.js's shared delegated handler for free — no per-page JS needed to wire the dismiss button, though a caller with its own reveal/hide logic (e.g. bulletin.html's share toast) may still bind additional listeners; the two do not conflict since both just toggle the same ``hidden`` class. ARIA: kind in ("error", "warning") → role="alert" aria-live="assertive" otherwise → role="status" aria-live="polite" Display notes: ``flex`` is NOT baked into the base class. ``sw_register.js`` toggles ``hidden``/``flex`` on reveal (see static/js/sw_register.js lines 46–67), and the HTMX error JS only removes ``hidden``. Adding ``flex`` here would break both patterns. The ``body_template`` panel variant is the one exception: it needs a flex context for ``flex-wrap`` + ``basis-full`` to do anything, so it bakes ``flex`` in alongside ``hidden``. Both callers' patterns still work — Tailwind emits ``.hidden`` last within the display group, so it wins whenever both classes are present, and revealing is still "remove ``hidden``". {% endcomment %}
