{% load i18n %} {% comment %} public/partials/_map_download_control.html — the "Download basemap" control for the currently-focused region (SNOW-521, relocated since). A member of the bottom-right control stack (#map-controls-br in _map_embed.html), sitting beside the layers pill: the layers menu is the cache-state dashboard, and this is the other control that writes to that cache. It was previously a roundel in the region-readout row (_season_ribbon.html) named .region-readout-download; both the placement and the name moved together. Takes no context. An earlier iteration rendered one of these per breadcrumb tier and took a ``tier`` argument; only the micro (leaf) tier survived — Major/Minor were dropped because their per-tier detail floors made the sizes non-monotonic with containment, which read as a bug. Unlike its predecessor this is NOT hidden until a region is focused: it is always present and starts in the "no-region" state, so the stack's composition doesn't shift as the user selects and deselects regions. map.js's mapDownloadControlInit drives data-download-state (no-region/idle/busy/done/disabled/offline) and rewrites the title/aria-label to match — the done state is probed from real BASEMAP_PINNED_CACHE contents, never a stored flag. Styled in static/css/map.css. The server-rendered label below is the nothing-focused wording, which is the correct first-paint state: map.js only adopts a region once regions.geojson has loaded. It also relabels for the other "no-region" cause — a focused region whose properties.download is null. {% endcomment %}
