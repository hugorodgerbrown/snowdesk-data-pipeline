# Sentinel Bulletins

This directory contains **nine hand-picked "sentinel" bulletin artefacts** — three
per upstream source (SLF, ALBINA, Météo-France) — that each illustrate a distinct
structural variant.  They exist to:

1. Give developers concrete examples of each variant when reading or extending the
   parsers and render model.
2. Act as a regression harness: `test_sentinel_round_trip.py` verifies that every
   `source.json` passes through `build_render_model()` without raising, and that
   every MF `source.xml` round-trips through `parse_dpbra_xml()` back to its
   committed `source.json`.

---

## Variant taxonomy

| Label | Short name | What makes it that variant |
|---|---|---|
| **A** | single-level / single-problem | One danger rating covering all elevations; one active problem type. |
| **B** | elevation-band split | Two danger ratings, each applying to a different elevation band (no time split). |
| **C** | split-day + multi-problem | Danger ratings differ across `all_day`/`earlier`/`later` periods *and* at least two distinct avalanche problem types are present. |

## Directory layout

```
tests/sentinels/
  README.md                               ← this file
  test_sentinel_round_trip.py             ← parametrised smoke test
  slf/
    A-single-level/
      source.json    ← raw CAAML bulletin record (as stored in ndjson archive)
      source.pdf     ← PDF published by SLF on the bulletin's validity day
      README.md      ← bulletinID, date, region, variant justification, PDF URL
    B-subdivision-plus/   (same shape)
    C-split-day-multi-problem/   (same shape)
  albina/
    A-single-level/   (same shape)
    B-elevation-band-split/
    C-split-day-multi-problem/
  meteofrance/
    A-single-level/
      source.xml     ← raw DPBRA XML from Météo-France
      source.json    ← output of parse_dpbra_xml(source.xml) at commit time
      source.pdf     ← PDF published by Météo-France
      README.md
    B-elevation-band-split/   (same shape)
    C-split-day-multi-problem/   (same shape)
```

## How to add a new sentinel

1. Identify the bulletin in the relevant ndjson archive (or obtain the upstream
   XML for MF).
2. Create a new subdirectory under the appropriate source folder using the naming
   convention `{Variant}-{slug}` (e.g. `D-avalanche-cycle`).
3. Add `source.json` (and `source.xml` for MF), `source.pdf`, and `README.md`
   following the pattern of an existing sentinel.
4. The smoke test in `test_sentinel_round_trip.py` is fully parametrised — it will
   automatically pick up the new `source.json` and `source.xml` without any code
   change.
5. Run `poetry run tox -e test -- tests/sentinels/` to confirm the new sentinel
   passes before committing.
