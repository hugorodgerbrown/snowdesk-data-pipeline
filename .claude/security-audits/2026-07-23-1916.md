### Medium

#### M1 — Content Security Policy runs report-only in production by default
**Location:** `config/settings/production.py:98-99`, `render.yaml:79-80`
**CWE:** CWE-693 (Protection Mechanism Failure)
**Evidence:**
```python
# production.py
CSP_ENABLED = config("CSP_ENABLED", default=True, cast=bool)
CSP_REPORT_ONLY = config("CSP_REPORT_ONLY", default=True, cast=bool)
```
`render.yaml` declares `CSP_REPORT_ONLY` with `sync: false`, i.e. it must be
set by hand in the Render dashboard. Until an operator explicitly sets it to
`False`, the browser receives `Content-Security-Policy-Report-Only` and the
policy blocks nothing.
**Impact:** The CSP defence-in-depth layer against XSS/data-exfiltration is
inert. Actual XSS exposure is already low (provider prose is bleach-sanitised,
no user free-text is rendered), so this is a hardening gap rather than an
active vulnerability — hence Medium, not High.
**Recommendation:** Once violation reports have stabilised, set
`CSP_REPORT_ONLY=False` in the Production env group. Separately, retire
`style-src 'unsafe-inline'` (`base.py:592`) by moving the map's inline
`style=""` swatches to classes so the enforced policy is meaningful.

### Low / informational

#### L1 — CI workflows lack an explicit least-privilege `permissions:` block
**Location:** `.github/workflows/{ci,js,e2e,lighthouse,lint-guards,security-audit}.yml`
**CWE:** CWE-732. Six of seven workflows set no top-level `permissions:`, so
the job `GITHUB_TOKEN` inherits the repository/org default (potentially
read-write). `release.yml` correctly scopes `contents: write`.
**Recommendation:** Add `permissions: contents: read` at the top of each
workflow (elevate per-job only where a step needs write).

#### L2 — GitHub Actions pinned by mutable tag, not commit SHA
**Location:** all workflows — e.g. `actions/checkout@v7`,
`gitleaks/gitleaks-action@v3`, `astral-sh/setup-uv@v8.3.2`.
**CWE:** CWE-829. A moved tag on a third-party action executes new code in CI.
Official `actions/*` at major tag is lower-risk; third-party actions
(`gitleaks`, `astral-sh`) are the ones worth SHA-pinning.
**Recommendation:** Pin third-party actions to a full commit SHA with a
`# vX.Y.Z` comment; Dependabot can keep them current.

#### L3 — Admin at default `/admin/` path with password-only staff auth
**Location:** `config/urls.py` (default admin mount), `base.py:250-255`.
No 2FA, no per-view rate-limit on the admin login form; the admin surface is
excluded from CSP (`base.py:620-625`, documented, low blast radius).
**Impact:** Low — staff-only, protected by `AUTH_PASSWORD_VALIDATORS`; brute
force is bounded by password strength but not by a login throttle.
**Recommendation:** Consider a non-default admin path and 2FA
(`django-otp`) if the staff population grows. Informational at current scale.

#### L4 — Unsubscribe tokens never expire (by design)
**Location:** `accounts/services/token.py:151-178` (`verify_unsubscribe_token`
calls with `max_age=None`).
The token encodes `email|region_id` and is signed with a dedicated
`SALT_UNSUBSCRIBE`, so it cannot be replayed against another flow. A leaked
historical email lets its holder unsubscribe that address from that region —
no PII disclosure beyond what an email holder already has.
**Impact:** Low, and intentional (a subscriber must be able to opt out from
any past email). Recorded for completeness.
**Recommendation:** None required. If a future review wants revocability,
add a per-subscriber token version to the signed payload.

#### L5 — GZip enabled on dynamic responses over HTTPS (BREACH class)
**Location:** `config/settings/production.py:29-32`.
The module comment already flags this. Django's per-request masked CSRF
tokens and the fact that magic-link secrets travel in URL paths (not
reflected bodies) mitigate the practical BREACH vector.
**Recommendation:** Keep the documented invariant: never add an authenticated
page that reflects user-supplied input alongside a secret in the same
compressed response.

#### L6 — `SECURE_PROXY_SSL_HEADER` trusts `X-Forwarded-Proto`
**Location:** `config/settings/production.py:83`.
Correct and required for Render's TLS-terminating edge. Only exploitable if an
attacker can reach gunicorn directly, bypassing the Render proxy — not
possible in the Render network topology. Informational.

## Recommendations beyond fixes

1. Add `gitleaks` and `pip-audit` to the `.venv` dev group (PATH-reachable) so
   the standalone Phase-0 invocations work without the tox wrapper.
2. Flip CSP to enforcing (M1) and remove `style-src 'unsafe-inline'` — the
   single highest-value hardening step.
3. Add `permissions: contents: read` to every workflow (L1) and SHA-pin
   third-party actions (L2); let Dependabot maintain them.
4. Keep `tox -e sast` and `tox -e audit` as required CI checks (they already
   exist) so this posture does not regress.
5. Re-run this audit after any change that introduces a user free-text field
   (observations/comments) — the current no-stored-XSS conclusion depends on
   the absence of user-rendered prose.
