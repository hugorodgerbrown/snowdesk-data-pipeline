### Medium

#### M1 — Content-Security-Policy is report-only in production and permits inline styles
**Location:** `config/settings/production.py:98-99`, `config/settings/base.py:532-572`
**CWE:** CWE-1021 / CWE-693 (Protection Mechanism Failure)
**Evidence:**
```python
# production.py
CSP_ENABLED = config("CSP_ENABLED", default=True, cast=bool)
CSP_REPORT_ONLY = config("CSP_REPORT_ONLY", default=True, cast=bool)   # <- report-only
# base.py CSP_DEFAULTS
"style-src": ["'self'", "'unsafe-inline'"],
```
**Impact:** In report-only mode the browser sends violation reports but does **not** block anything, so CSP provides no runtime XSS containment. `script-src` is correctly nonce-based, which is the important half — but `style-src 'unsafe-inline'` would also weaken the policy once enforced (CSS-based data exfiltration / UI redress). The app's output-escaping and bleach sanitisation are the real XSS defences; CSP here is the second layer that is currently inert.
**Recommendation:** After the report-only period has surfaced a stable violation set, set `CSP_REPORT_ONLY=False` in the production env group to enforce. Track removal of `'unsafe-inline'` from `style-src` (the code comment at `base.py:543-547` already flags this as a follow-up: refactor `map.html` inline `style=""` and MapLibre programmatic styles into classes/nonces). Until enforced, treat CSP as documentation, not a control.

### Low

#### L1 — GitHub Actions workflows lack a least-privilege `permissions:` block
**Location:** `.github/workflows/ci.yml`, `e2e.yml`, `lighthouse.yml`, `lint-guards.yml`, `security-audit.yml` (only `release.yml:27` sets one)
**CWE:** CWE-732 (Incorrect Permission Assignment)
**Impact:** Without a top-level `permissions:` block these jobs inherit the repository/organisation default `GITHUB_TOKEN` scope, which can be read-write. A compromised action or dependency in the job could then push code, edit releases, or open PRs.
**Recommendation:** Add `permissions: {contents: read}` at the top of each workflow (widen per-job only where a step needs write, e.g. artifact upload / release creation). No `pull_request_target` is used anywhere, so there is no untrusted-checkout RCE path — this is pure least-privilege hardening.

#### L2 — Third-party / first-party actions pinned to mutable version tags, not commit SHAs
**Location:** all `.github/workflows/*.yml` (`actions/checkout@v7`, `actions/setup-python@v6`, `gitleaks/gitleaks-action@v3`, `astral-sh/setup-uv@v8.3.2`, …)
**CWE:** CWE-829 (Inclusion of Functionality from Untrusted Control Sphere)
**Impact:** A moved tag (tag re-point / repo compromise) silently changes the code that runs in CI with the `GITHUB_TOKEN`. `gitleaks/gitleaks-action@v3` (third-party, major-tag) is the highest-value target.
**Recommendation:** Pin at least the third-party actions (`gitleaks`, `astral-sh/setup-uv`) by full commit SHA with a comment naming the version. First-party `actions/*` are lower risk but SHA-pinning them is the strict best practice.

#### L3 — Application loggers run at DEBUG in production
**Location:** `config/settings/base.py:794-833` (loggers `core`, `regions`, `bulletins`, `accounts` set `"level": "DEBUG"`); not overridden in `production.py`
**CWE:** CWE-532 (Information Exposure Through Log Files)
**Impact:** Production writes DEBUG-level records to `logs/*.log` on the (ephemeral) Render disk. Current DEBUG lines are safe — emails are masked via `mask_email()` and `token.py` logs only the salt, never token values — but the DEBUG floor means any future unmasked `logger.debug(...)` added by a developer ships PII/token material to disk with no review gate.
**Recommendation:** Override these loggers to `INFO` (or `WARNING`) in `production.py`, or make the level env-driven with an `INFO` production default. Keeps the DEBUG detail available locally without lowering the production floor.

#### L4 — Unsubscribe tokens never expire
**Location:** `accounts/services/token.py:151-178` (`verify_unsubscribe_token` calls `verify_token(..., max_age=None)`)
**CWE:** CWE-613 (Insufficient Session Expiration)
**Impact:** By design a subscriber can opt out from a link in a months-old email, so the token is permanent. Blast radius is bounded to a single action (unsubscribe a region) with no account takeover, and the token is HMAC-signed so it cannot be forged. Low, and an accepted trade-off.
**Recommendation:** No change required; documented here for completeness. If ever tightened, add a generous `max_age` (e.g. one season) rather than `None`.

### Low / informational

#### I1 — `prose_body` returns raw, unsanitised SLF HTML and relies on every caller chaining `|snowdesk_html`
**Location:** `public/templatetags/snowdesk_html.py:116-132`
**Impact:** All current callers comply (`_tendency_body.html:25` chains `|prose_body|snowdesk_html`; verified no template renders `prose_body` output un-sanitised). It is a latent footgun: a future template that forgets the `|snowdesk_html` step would render provider HTML unescaped. External SLF prose is the exact content invariant #1 protects.
**Recommendation:** Either make `prose_body` return a sanitised `SafeString` itself, or add a `ds-lint`/grep guard that fails when `prose_body` appears without a following `snowdesk_html`.

#### I2 — PostHog exception capture is on by default in production
**Location:** `config/settings/base.py:268-280`
**Impact:** `POSTHOG_MW_CAPTURE_EXCEPTIONS` defaults `True`, shipping stack traces to PostHog EU. Frame-local capture (`POSTHOG_CAPTURE_EXCEPTION_CODE_VARIABLES`) is correctly `False`, so only traces (not variable values) leave the process. Residual risk: an exception message string could embed user data. Already reasoned about in the code comments.
**Recommendation:** Accept as-is, or review exception-message construction on token/email paths to confirm no address is interpolated into an exception string that would then transit to PostHog.

#### I3 — Local tool coverage gap: `pip-audit` and `gitleaks` not in `.venv`
**Location:** environment (`.venv/bin/`)
**Impact:** The dependency and secret scans in this audit were run via `uvx pip-audit` and a regex fallback rather than the project's `tox -e audit` / pre-commit `gitleaks`. CI still runs both (`security-audit.yml` uses `gitleaks-action`; `tox -e audit` provisions its own env), so pipeline coverage is intact — only the local developer loop is affected.
**Recommendation:** `uv sync` (or add `pip-audit` to the dev group) and `pre-commit install` so `tox -e audit` / `tox -e sast` and the gitleaks hook run locally without ad-hoc invocation.

## Snowdesk-specific threat-surface results

- **SLF / ALBINA / Météo-France ingest** — No SSRF: target URLs come from `settings.*_API_BASE_URL` (env), never from request or bulletin content. `requests.get` uses default `verify=True` and a 30 s timeout (`slf_fetcher.py:63,136`; `meteofrance_fetcher.py:58,219`). XML parsed with `defusedxml.ElementTree.fromstring` (`meteofrance_translator.py:38,145`) — XXE/entity-bomb neutralised. Unknown regions raise loudly rather than auto-create; malformed entries validated before any DB write (`slf_fetcher.py:254-285`).
- **Resend email** — Header injection not reachable: `send_mail(recipient_list=[email], subject=<constant>)`, Django escapes headers; no manual header assembly. Magic-link/reset/change URLs built from `SITE_BASE_URL + reverse() + signed token` — no user-controlled scheme, so no `javascript:`/open-redirect. All email-trigger views throttled 3/min/IP.
- **Anthropic / MCP** — `POST /api/mcp/` is a read-only JSON-RPC tool server exposing Snowdesk data; it does **not** proxy any model call, so there is no prompt-injection sink. `csrf_exempt` justified (no cookies/state), `require_POST`, 60/min/IP rate limit, `Cache-Control: no-store` (`mcp_server/views.py`).
- **Subscription tokens** — `TimestampSigner` with per-purpose salts (account-access, unsubscribe, email-verification, password-reset, email-change). Password-reset token embeds an HMAC of the current password hash + last-login → auto-invalidates on use (single-use) and is compared with `constant_time_compare` (`token.py:186-260`). Email-change binds `user_pk|new_email`. No timing side-channel (constant-time compare; signature check is the gate). TTL enforced via `ACCOUNT_TOKEN_MAX_AGE` on every short-lived flow; only unsubscribe is intentionally permanent (L4).
- **HTMX partials** — All mutating fragments require CSRF (only MCP/telemetry are exempt, both stateless). `require_htmx` rejects non-HTMX requests with 400. `hx-*` attributes reviewed: `var-in-href` semgrep hits are Django-autoescaped `{{ url }}` values, not `mark_safe`. No `HX-Redirect`/`HX-Location` value derived from user input.
- **Rate-limit coverage** — Complete. Decorator form (`@ratelimit(..., block=False)`) is correctly paired with an explicit `if getattr(request, "limited", False): return 429` check in every guarded view (verified across `accounts`, `favourites`, `observations`). Email-trigger views use the programmatic `get_usage(...)` throttle (3/min). No unthrottled state-changing endpoint found.

## Suppressed findings (semgrep, 211 raw → 0 surfaced)

- **`template-blocktranslate-no-escape` (166) + `template-translate-as-no-escape` (2)** — false positive. Django `{% blocktranslate %}` auto-escapes interpolated variables; these are ordinary i18n blocks, no `|safe`.
- **`var-in-href` (25)** — false positive. All are Django-autoescaped `{{ url }}` / `{{ token_url }}` values built server-side from `reverse()` + signed tokens; none use `mark_safe` and none carry a user-controlled scheme.
- **`python-logger-credential-disclosure` (14)** — false positive. Inspected every hit: emails logged only via `mask_email()`; `token.py` logs the salt label, never token values; others log PKs / event names / credential IDs. No secret or raw PII reaches a logger.
- **`unvalidated-password` (2)** — `bulletins/management/commands/seed_test_data.py` dev-seeding only; not a runtime auth path.
- **`use-defused-xml` / `use-defused-xml-parse` (2, ERROR)** — `docs/research/meteofrance/_parse_samples.py`, a one-off research script, not shipped code. The production translator already uses `defusedxml` (`meteofrance_translator.py:38`).
